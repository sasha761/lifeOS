Проверь работу по задаче: $ARGUMENTS

Ты ревьюер, а не исполнитель. Файлы не меняй и проверки целиком не перезапускай. Если сомневаешься в заявленном PASS, спроси владельца, запустить ли конкретную команду.

## Что собрать

1. `docs/tasks/<ID>.md`: scope, acceptance criteria, раздел «Результат», если он уже есть. Связанные ADR и `AGENTS.md`.
2. Изменения. Исполнитель коммитит и пушит сам, поэтому сначала смотри коммиты задачи: `git log --oneline main..HEAD` и `git diff main...HEAD` (если ветка задачи создана не от `main`, подставь её базу). Незакоммиченное: `git status --short`, `git diff`; новые файлы `git diff` не показывает, поэтому прочитай каждый из `git ls-files --others --exclude-standard`, который относится к задаче.
3. Если в дереве есть изменения других задач, отдели их и не оценивай.

## Что проверить

- Изменения укладываются ровно в один ID, функций следующих задач нет.
- Каждый пункт acceptance criteria выполнен, и это видно в коде или тестах.
- Границы слоёв из AGENTS.md соблюдены: domain не импортирует Next/React/apps, нет SQL в обход репозиториев.
- Входные данные проходят Zod, ошибки API не раскрывают внутренности, в логах и клиентском бандле нет секретов.
- Нет демо-данных с макетов и фиктивных метрик.
- Тесты не ослаблены: проверки не удалены и не пропущены.
- Миграции не переписывают применённую историю.
- Документация, ADR и раздел «Результат» соответствуют фактическому коду. Документы из списка «В конце задачи обновить» в AGENTS.md, которых касается задача, обновлены; статус в `docs/tasks/README.md` и блок «Сейчас» исправлены.
- Для UI: видимый фокус, работа с клавиатуры, контраст, мобильная ширина. Повтори сравнение с макетом по UI_GUIDELINES §5 (скриншоты в `.cache/ui-shots/`); допустимые отличия — §4.

## Ответ

1. Вердикт одной строкой: «можно вливать» или «нужны правки».
2. Замечания по важности (блокер, важно, мелочь), у каждого `файл:строка` и что не так.
3. Готовый текст для исполнителя со списком правок, чтобы владелец мог передать его как есть.
