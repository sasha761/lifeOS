## 16. Дизайн-система LifeOS

### 16.1. Характер

Плотный «рабочий» интерфейс: тёмные поверхности с фиолетовым подтоном, тонкие границы, компактные строки, цвет используется **только для смысла** (статус, сфера, нагрузка), а не для декора. Крупный воздух — между секциями; внутри списков — плотно.

**Сферы LifeOS** (иконка + точка, не заливка): languages `--accent`, finance `--st-green`, work `--st-blue`, projects `--st-amber`, skills `--st-cyan`, health `--st-red`.

**Тема «Indigo»** (в третьем ролике интерфейс заметно светлее и сине-лиловый): фон `#2A2A55`, поверхности `#34346A` / `#3E3E7A`, блоки календаря `#5B7BE0`, текст `#F2F2FF`. Делается той же системой токенов, переключается в настройках; в MVP не обязательна.

**Light-тема** (вторично, для дневного режима и Telegram light): `--bg #F7F5FB`, `--surface-1 #FFFFFF`, `--surface-2 #F1EEF7`, `--border #E3DDEE`, `--text #1C1726`, `--text-2 #6B6180`; статусные цвета на 8–10% темнее для контраста 4.5:1.

> Контраст проверить в LFS-103: `--text-2` на `--surface-2` ≥ 4.5:1, статусные точки — ≥ 3:1 к фону.

### 16.3. Типографика

Шрифт **Inter** (variable, `font-feature-settings: "cv11", "ss01"`, `tabular-nums` для чисел и времени). Кириллица поддерживается.

| Роль | Размер / line-height | Вес |
|---|---|---|
| `display` (заголовок раздела: «Задачи», «Поиск работы») | 26/32 | 700, letter-spacing −0.02em |
| `h2` (секции: «План дня») | 17/24 | 600 |
| `metric` (крупное «1 из 7», числа прогресса) | 32/36 | 700, tabular |
| `body` / название карточки | 14/20 | 500–600 |
| `body-sm` (описания) | 13/18 | 400 |
| `meta` (даты, проект, счётчики) | 12/16 | 500, `--text-2` |
| `micro` (бейджи, подписи шкал) | 11/14 | 600, uppercase не используем |

### 16.4. Сетка, отступы, формы

- База отступов **4px**: 4 / 8 / 12 / 16 / 24 / 32 / 48. Внутри строки — 8–12, между секциями — 24–32.
- Радиусы: `--r-sm 6px` (бейджи, чекбоксы), `--r-md 10px` (карточки, строки, поля), `--r-lg 14px` (панели, модалки), `--r-pill 999px` (сегментированные переключатели).
- Высоты: строка задачи 44px (2 строки текста — 56px), карточка воронки 52px, кнопка 32px (sm 28), верхняя полоса 48px.
- Границы 1px `--border`; тени почти не используем (только у поповеров: `0 8px 24px rgb(0 0 0 / .35)`).
- Layout desktop (уточнено по скриншотам): **минимальная верхняя полоса без фона** 56px. Слева логотип и текущее пространство («LifeOS · Работа»), справа круглые pill-кнопки с иконкой: «Задачи», «Проекты», «Ассистент» и шестерёнка настроек. Активная кнопка светлее. Контент центрирован, max-width ~1180px. **Правая панель ассистента** 400–440px сужает экран, а не перекрывает его. В шапке раздела справа — вторичная pill-кнопка «✦ Задача / Проект с ассистентом» и круглая «+».
- Почти все переключатели и кнопки — **pill** (r 999px), включая вкладки проекта (Обзор / Воронка / Задачи 16 / История / О проекте / Файлы 34 в одном округлом контейнере).
- Mobile / Telegram Mini App: та же палитра, нижняя навигация, панель ассистента — полноэкранный sheet.

### 16.6. Motion

- Длительности: 120ms (hover, нажатие), 180ms (раскрытие групп, вкладки), 240ms (панель ассистента, модалки). Easing `cubic-bezier(.2,.8,.2,1)`.
- Перетаскивание карточек: поднятие `scale(1.02)` + тень; колонка-приёмник подсвечивается tint.
- Чекбокс: заполнение + зачёркивание названия 180ms, затем строка уезжает в «Выполнено».
- Переход карточки воронки на новую стадию (от AI-пайплайна) — короткая вспышка tint нужного цвета, без конфетти.
- `prefers-reduced-motion` — все переходы сводятся к opacity.

### 16.7. Реализация (LFS-211, уточнено по фактическому репозиторию)

Проект уже использует Tailwind 4 (`@theme inline` в `apps/web/app/globals.css`) и shadcn `base-nova` с CSS-переменными. Отдельный `tailwind.config` и `packages/config/design-tokens.css` **не нужны**: Mini App живёт в том же `apps/web`, поэтому токены задаются один раз в `globals.css`.

1. Существующие shadcn-переменные перекрашиваются: `--background → #16131D`, `--card → #1F1A2A`, `--muted → #282236`, `--secondary → #322B42`, `--foreground → #F2EDF8`, `--muted-foreground → #B4A8C8`, `--border → #372F47`, `--primary → #8B7CF6`, `--primary-foreground → #16131D`, `--ring → #9D90F8`, `--destructive → #E5605E`, `color-scheme: dark`.
2. Новые переменные добавляются рядом: `--surface-2`, `--surface-3`, `--border-strong`, `--text-3`, `--st-blue/amber/orange/red/green/cyan/gray`, `--today`, и пробрасываются в `@theme inline` как `--color-surface-2`, `--color-st-blue` и т.д., чтобы работали классы `bg-surface-2`, `text-st-blue`, `bg-st-blue/15`.
3. Шрифт Inter — без запросов к Google в рантайме: `next/font` (локально самохостит при сборке) или пакет `@fontsource-variable/inter` с точной версией в lockfile. Решение фиксируется в ADR-011.
4. Светлая тема — не в первой итерации; её значения остаются в §16.2 для будущего `[data-theme="light"]`.

**LFS-211 (первая итерация):** токены, Inter, dark по умолчанию, новая оболочка (верхняя полоса с pill-кнопками вместо левого сайдбара), pill-переключатели, перекраска существующих экранов (auth, цели, сферы, настройки, кабинет). Компоненты будущих модулей (`TaskRow`, `KanbanColumn`, `LoadMeter`, `AchievementBadge`…) **не** создаются заранее: они появляются в своих этапах.

## 17. Модуль Tasks (таск-трекер)

### 17.1. Что берём из референса

1. **«Сегодня» как экран принятия решения:** сводка одной строкой → панель дня (прогресс, серия, нагрузка, «Разгрузить») → «План дня».
2. **Календарь недели** со штриховкой занятого времени.
3. **Детали задачи** в двухколоночной панели: поля/описание слева, заметки и ресурсы справа.
4. **Проекты** как сетка карточек-папок.
5. **Мой прогресс**: серия, график, полосы.
6. **Ассистент**: разбор созвона/заметки → задачи; перестройка плана при смене приоритета.

### 17.2. Экраны и маршруты

| Маршрут | Экран |
|---|---|
| `/tasks` (`?view=today`) | Сегодня |
| `/tasks?view=calendar` | Неделя / день |
| `/tasks?view=all` | Все задачи: список с группировкой (проект / срок / статус) + фильтры |
| `/tasks?view=trash` | Корзина (soft delete, восстановление 30 дней) |
| `/tasks/[id]` | Детали задачи (панель поверх списка, отдельный URL) |
| `/projects`, `/projects/[id]` | Проекты-папки; внутри вкладки Обзор / Доска / Задачи / История / Инфо / Файлы |
| `/progress` | Мой прогресс (общий для всех сфер) |

**Экран «Сегодня»:**

- Заголовок «Сегодня» + дата, ниже сводка с выделенными числами: «**1** встреча, **6** задач на **8 ч 30 мин**, 3 без оценки, **свободно после 15:00.**»
- Левая колонка 300px — `DayCard` (§16.5).
- Правая часть: карточка «План дня» со счётчиком. `TaskRow`: круглая отметка (частично залитая — «в процессе»), название, под ним цветной чип проекта, жёлтый чип статуса («в процессе», «в это время», «перенос»), оценка. Встреча — строка с обратным отсчётом сверху («Через 1 ч 10 мин · 10:00–11:00») и участниками. Внизу сворачиваемые группы-кнопки «✓ Выполнено сегодня 1» и «◷ Ждём 4».
- Быстрый ввод сверху: «Добавить задачу… (Enter)», парсинг «завтра 15:00 #lifeos ~1ч».

### 17.3. Правила расчёта (честные метрики, §5 плана)

- **Ёмкость дня** = рабочие часы из настроек (по умолчанию 09:00–17:00 минус перерыв = 7 ч) − встречи в календаре.
- **Нагрузка** = Σ `estimate_minutes` задач, запланированных на сегодня и не выполненных + выполненные сегодня (факт). Задачи без оценки **не считаются нулём** — показываются отдельно «3 без оценки», шкала помечается «неполные данные».
- Зоны: < 70% — зелёная, 70–100% — жёлтая, > 100% — красная («перегрузка»).
- **Разгрузить**: алгоритм (детерминированный, не LLM) выбирает кандидатов на перенос — без жёсткого срока сегодня, низкий приоритет, большая оценка — и ближайшие дни со свободной ёмкостью. Результат показывается как `ActionPreview` (было/станет), применяется только после подтверждения. LLM-ассистент может *объяснить* или *изменить* предложение, но расчёт ёмкости — код.
- **Серия** = подряд идущие дни, где выполнена ≥ 1 запланированная задача (порог настраивается). Методика видна по hover.
- «1 из 7» = выполнено / запланировано на сегодня (включая перенесённые на сегодня).

### 17.3a. Геймификация (по скриншотам «Мой прогресс»)

В роликах автор прямо говорит, что «поработал с геймификацией». На экране «Мой прогресс» (он же главный экран LifeOS):

1. Сводка одной фразой: «23 задачи за неделю. 5 дней в ритме, серия 18 дней. Лучше прошлой недели на 4.»
2. **Карточка серии** (тёплый градиент): огонь, «18 дней подряд», кружки дней недели, лучшая серия, ближайший значок («До “Месяц в огне” 12 дней»).
3. **График недели**: число закрытых + столбики по дням в трёх цветах (по плану / сверх плана / перенесено), переключатель Неделя / Месяц.
4. **Цели недели**: 2–4 строки с иконкой и полосой («Дни в ритме 5/7», «Закрыть просроченное 6/10», «Закрыть самую тяжёлую задачу 1/1»).
5. **Рекорды**: лучшая неделя, лучший день, лучший месяц, всего закрыто.
6. **Сферы жизни**: прогресс целей по сферам (это LifeOS-специфика: не «уровень жизни», а прогресс конкретных целей с источником).
7. **Достижения**: шестиугольные значки («Первый шаг», «Пять за день», «В огне», «Разгон», «Чемпион недели», плюс доменные: «Норвежский B1», «Первый оффер»).

**Правила честности (§5 плана):** каждое достижение и рекорд — детерминированное правило над записями (`tasks.completed_at`, `lesson_sessions`, `applications.stage`), видимое в подсказке. AI не начисляет значки. Перенос задач не ломает серию, если в день выполнена хотя бы одна; правило задаётся в настройках.

**Данные:** `achievement_definitions` (в коде: key, title, rule, icon, domain_key), `user_achievements` (user_id, key, earned_at, evidence_ref, UNIQUE user+key), `weekly_goals` (user_id, week_start, kind, target, title). Рекорды и серия считаются запросами, без снимков.

## 18. Модуль Job Search (резюме, воронка, AI-пайплайн откликов)

### 18.1. Что берём из референса

- Поиск работы — это **проект** в сфере `work` со своей **воронкой** (как в CRM): Найдено → Письмо готово → Отправлено → Ответили → Интервью → (свёрнуто) Оффер / Отказ / Архив.
- Переключатели «Вакансии / Компании» со счётчиками, «+ Воронка» (можно вести несколько воронок: например, «Норвегия» и «Remote»).
- Агент сам находит вакансии и пишет **отдельное письмо под каждую**; если сайт блокирует ботов — честно говорит «нужна ручная подача» и даёт готовый текст.

### 18.2. Важно: правовые и ToS-риски автоподачи

| Площадка | Что разрешено | Вывод для LifeOS |
|---|---|---|
| **LinkedIn** | Пользовательское соглашение запрещает ботов, скрейпинг и автоматизацию действий (включая Easy Apply). Риск — блокировка аккаунта. | Только ручная подача пользователем; LifeOS готовит письмо и ведёт карточку. Импорт вакансии — пользователь вставляет ссылку/текст. |
| **Indeed, Glassdoor** | ToS запрещают автоматический сбор и действия ботов. | Так же: ручная подача. |
| **FINN.no** | Скрейпинг/автоматизация запрещены условиями. | Ручная подача; добавление вакансии по ссылке. |
| **NAV / arbeidsplassen.no** | Есть публичный фид вакансий (API для чтения). Подача — через работодателя. | **Источник поиска** вакансий через официальный API. |
| **hh.ru** (если нужен рынок СНГ) | Официальный API с OAuth, в т.ч. отклики соискателя — по правилам API и лимитам. | Возможна **API-подача**, но условия для приложений соискателей hh.ru менялись и ужесточались — проверить актуальные правила до этапа 12; без подтверждённого разрешения считать «ручная подача». |
| **Публичные job boards ATS** (Greenhouse, Lever, Ashby, Teamtailor) | Публичные API **чтения** вакансий. Подача через форму работодателя (часто с CAPTCHA). | Источник поиска; подача — ручная или по email, если указан. |
| **Email работодателю/рекрутеру** (адрес указан в вакансии) | Законно, если письмо персонализировано и отправляется с почты пользователя. | **Основной канал авто-отправки** — Gmail/Outlook API от имени пользователя, после его подтверждения. |

Дополнительно:

- **Обход CAPTCHA, антибот-защиты, автозаполнение чужих форм через headless-браузер — не делаем.** Это прямое нарушение условий и риск бана аккаунта пользователя.
- **GDPR:** контакты рекрутеров — персональные данные; хранить минимально, с источником, удалять вместе с проектом; текст резюме не отправлять провайдерам LLM, которые используют данные для обучения.
- **Честность писем:** AI не выдумывает опыт. Письмо строится только из фактов резюме/профиля; спорные утверждения подсвечиваются при проверке.
- **Норвегия/ЕС:** массовые одинаковые письма без персонализации могут подпадать под правила о нежелательной рассылке — поэтому лимиты и персонализация обязательны.

### 18.3. Уровни автономии (настройка в проекте)

| Уровень | Что делает AI | Что делает пользователь |
|---|---|---|
| **L0 — Трекер** | ничего, только воронка | всё вручную |
| **L1 — Черновики** (по умолчанию) | находит, оценивает соответствие, пишет письмо | проверяет и подаёт сам |
| **L2 — Пакетное подтверждение** | готовит пачку (например, 10) писем | одним экраном одобряет/правит/отклоняет; одобренные **email**-отклики отправляются автоматически |
| **L3 — Авто-email в рамках правил** | сам отправляет email-отклики, если match ≥ порога и вакансия из белого списка источников | задаёт правила, дневной лимит (по умолчанию ≤ 10/день), может остановить |

На площадках из «запрещённой» колонки уровень всегда фактически L1: карточка получает статус «Нужна ручная подача» с готовым текстом и кнопкой «Открыть вакансию». Так работает и сценарий из рилса («сайт блокирует ботов → пишу сам»), только LifeOS **не пытается** обойти блокировку.

### 18.4. Пайплайн (worker + pg-boss)

```text
[search_profile]──► discover ──► dedupe ──► enrich ──► match/score ──► draft ──► review ──► send ──► track ──► classify reply
     (критерии)      (API-фиды,   (url hash,  (компания,  (резюме ×      (письмо,   (L1/L2/L3)  (email/  (Gmail     (ответ/отказ/
                      ссылки от    компания+   контакт,    требования,    CV-версия)            hh API/  read-only, интервью →
                      пользователя) должность)  язык)       0–100 + why)                         manual)  thread id)  стадия)
```

| Job | Вход → выход | Детали |
|---|---|---|
| `jobs.discover` | профиль поиска → `vacancies` | cron 1–2 раза/день; только разрешённые источники; пользователь может вставить ссылку/текст вакансии вручную |
| `jobs.dedupe` | новая вакансия → merge / new | ключи: нормализованный URL, (company, title, location) |
| `jobs.score` | вакансия + резюме → `match_score`, `match_reasons`, `gaps` | LLM structured output + жёсткие фильтры кодом (локация, язык, зарплата, исключённые компании) |
| `jobs.draft` | вакансия + резюме + профиль → `cover_letter` (версия) | язык письма = язык вакансии; ≤ 250 слов; ссылки на факты резюме; prompt_version фиксируется |
| `jobs.review` | → `pending_approval` | уведомление в Telegram: «5 писем готовы» → Mini App / Web экран пакетного ревью |
| `jobs.send` | approved → `sent` | email через OAuth-почту пользователя с CV-PDF; idempotency key на (application_id, channel); rate limit; при ошибке — `needs_manual` |
| `jobs.track` | входящие письма → привязка к application | read-only доступ к почте, только треды, начатые LifeOS, + поиск по домену компании |
| `jobs.classify` | ответ → `replied` / `interview` / `rejected` | LLM-классификация **предлагает** стадию; интервью → создаётся задача и событие календаря (с подтверждением) |
| `jobs.followup` | `sent` без ответа N дней → черновик follow-up | только предложение, не авто-отправка (кроме L3 с явной настройкой) |

| Таблица | Ключевые поля |
|---|---|
| `resumes` | user_id, title, language, base_markdown, structured_json (опыт, навыки, образование), pdf_file_ref, is_default, version |
| `job_search_profiles` | user_id, project_id, titles[], locations[], remote, languages[], salary_min?, exclude_companies[], sources[], autonomy_level, daily_send_limit, min_match_score |

### 18.6. Экраны

- **`/work/job-search`** — `PageHeader` (‹ Проекты, иконка портфеля в синем tint, «Поиск работы», ✎, закрепить, ⋯, подпись «Поиск новой работы с 3.11.2026»), вкладки проекта в pill-контейнере (Обзор / Воронка / Задачи 16 / История / Резюме / О проекте / Файлы 34), тулбар: «Вакансии 55 / Компании 30», ⋯, «+ Воронка», справа поиск, «+ Вакансия по ссылке», «+ Группа».
