# Codex и Claude Code в LifeOS

Над проектом работают два ИИ-исполнителя. Правила для обоих одни и те же: [AGENTS.md](../AGENTS.md)
и [DEVELOPMENT_WORKFLOW.md](DEVELOPMENT_WORKFLOW.md). Claude Code читает `CLAUDE.md`, а тот подключает
`AGENTS.md` через `@AGENTS.md`, поэтому правила не дублируются: менять их нужно только в `AGENTS.md`.
В `CLAUDE.md` остаётся только то, что касается самого Claude Code.

У Claude Code есть личная авто-память вне репозитория (`~/.claude/projects/…`); Codex её не видит.
Поэтому указание владельца, которое должны соблюдать оба агента, записывается в `AGENTS.md` или в нужный
документ `docs/` (например, допустимые отличия от макета — в UI_GUIDELINES §4), а не в память.

## Роли

На каждую задачу назначаются **один исполнитель и один ревьюер**.

- Исполнитель меняет код по одному LFS-ID и пишет отчёт.
- Ревьюер только читает diff и отчёт и пишет замечания. Сам он ничего не правит.
- Исполнитель сам коммитит и пушит ветку задачи, без вопроса ([AGENTS.md](../AGENTS.md), п. 8). Правки по замечаниям —
  новыми коммитами в ту же ветку. PR вливает владелец.

Роли назначает владелец; их можно чередовать от задачи к задаче.

## Правила совместной работы

1. **Не запускать двух агентов одновременно в одной папке.** Они перезаписывают файлы друг друга, а `git diff`
   смешивает их изменения.
2. **Перед стартом задачи предыдущая работа закоммичена.** Тогда `git diff` показывает только текущий LFS-ID
   и ревью получается честным.
3. **Параллельно — только разные LFS-ID в отдельных ветках через `git worktree`**, и только когда база закоммичена.
   В каждом worktree нужен свой `pnpm install`. PostgreSQL для тестов общий, поэтому `pnpm verify`
   и integration-тесты запускать по очереди.
4. Отчёт у обоих исполнителей одинаковый: «Структура результата» из `AGENTS.md`,
   плюс `git diff --stat` и `git status --short`.

## Цикл одной задачи

1. **Исполнитель.** Claude Code: `/lfs LFS-XXX`. Codex: `$lfs LFS-XXX` или `$lfs-auto` (см. ниже). Обе команды Codex
   выполняют ту же процедуру из `.claude/skills/lfs/SKILL.md`, поэтому отдельный промпт под каждую задачу не нужен.
   Если для задачи всё же есть `docs/tasks/LFS-XXX-CODEX-PROMPT.md`, его указания добавляются к процедуре.
   `LFS-211-CODEX-PROMPT.md` и `STAGE-02-FIRST-CODEX-PROMPT.md` — исторические, для выполненных задач.
2. Исполнитель показывает план, владелец отвечает «ОК», исполнитель пишет код, запускает проверки и отчитывается.
   В режиме `$lfs-auto` плана в чате нет: исполнитель записывает его в отчёт задачи и работает без остановок.
3. **Ревьюер.** Claude Code: `/lfs-review LFS-XXX`. Codex: `$lfs-review LFS-XXX`.
4. Владелец передаёт список правок исполнителю, тот исправляет.
5. Владелец смотрит результат (для UI — скриншоты и браузер) и вливает PR ветки задачи.

## Codex: команды и настройка

Команды Codex лежат в `.agents/skills/<имя>/SKILL.md`: Codex ищет скиллы репозитория в этой папке. Это короткие обёртки
над теми же процедурами из `.claude/skills/`, поэтому процесс у агентов один и меняется в одном месте. Список команд
показывает `/skills`, вызов — `$` и имя команды. Сам по себе, по смыслу запроса, Codex их не запускает:
в `agents/openai.yaml` каждой команды стоит `allow_implicit_invocation: false`.

| Команда | Что делает |
|---|---|
| `$lfs LFS-XXX` | То же, что `/lfs` у Claude Code: подготовка, план, «ОК» владельца, код, проверки, отчёт, коммит и пуш. Без номера Codex предлагает следующую задачу и ждёт подтверждения |
| `$lfs-auto` | Сам берёт следующую задачу по очереди и выполняет её целиком, до коммита и пуша, без остановок. Ровно одна задача. Можно указать номер: `$lfs-auto LFS-XXX` |
| `$lfs-review LFS-XXX` | То же, что `/lfs-review`: ревью без правок, замечания и вердикт |

### Что делает `$lfs-auto` по-другому

Правила — в [.agents/skills/lfs-auto/SKILL.md](../.agents/skills/lfs-auto/SKILL.md), исключение из п. 3 AGENTS.md
записано там же. Коротко:

- **Где не начинает работу**, а сразу отвечает: незакоммиченные изменения в дереве, неоднозначная очередь,
  невыполненные зависимости, задача «Вне очереди» или первая задача нового этапа.
- **План** не показывает в чате, а записывает в отчёт задачи.
- **Вопросы владельцу** решает сам самым осторожным вариантом. Каждое такое решение записывает в файл задачи
  в раздел «Решения исполнителя ($lfs-auto) — проверить владельцу» и перечисляет в ответе.
- **Без владельца не делает** и пишет в «Ручные действия»: новую зависимость, удаление данных, опасные git-команды,
  `pnpm db:migrate` к основной базе, правку Master Plan.
- **Падение проверки** чинит в рамках задачи. Если не вышло — коммитит и пушит с FAIL в сообщении и в отчёте,
  статус ✅ не ставит.
- **После задачи** следующую не начинает, PR не вливает.

### Перед первым `$lfs-auto`

1. **Предыдущая работа закоммичена**, Docker запущен: проверки поднимают тестовую базу (`pnpm db:test:up`).
2. **Режим без подтверждений.** Иначе Codex будет спрашивать разрешение на каждую команду и правку.
   - CLI: запускай `codex --sandbox workspace-write --ask-for-approval never` или переключи режим командой
     `/permissions`.
   - Приложение и расширение IDE: для этой папки выбери режим, в котором агент сам правит файлы и запускает команды.
3. **Сеть.** В режиме `workspace-write` сеть по умолчанию выключена. Она нужна для `git push`, `pnpm install`
   и подключения к PostgreSQL в Docker. Включается в `~/.codex/config.toml`:

   ```toml
   [sandbox_workspace_write]
   network_access = true
   ```

4. **Проверка:** `/skills` в Codex показывает `lfs`, `lfs-auto` и `lfs-review`.

**Из терминала одной командой**, без открытия чата:

```text
codex exec --sandbox workspace-write 'Выполни процедуру .agents/skills/lfs-auto/SKILL.md без аргументов: следующая задача по очереди.'
```

Одинарные кавычки работают и в PowerShell, и в Git Bash; знака `$` в строке нет, чтобы PowerShell не принял его за
переменную.

Здесь путь к файлу указан явно: в документации Codex не сказано, работают ли команды `$…` внутри `codex exec`. Флаги
своей версии Codex проверь через `codex exec --help`.

Если команды не видны (например, старая версия Codex), то же самое можно попросить текстом:
«Выполни процедуру .agents/skills/lfs/SKILL.md, аргументы: LFS-XXX».

## Claude Code: установка и запуск (Windows)

1. Установка в PowerShell (без прав администратора): `irm https://claude.ai/install.ps1 | iex`.
   Нужен платный план Claude (Pro или Max) или аккаунт Console. Проверка: `claude --version`, диагностика: `claude doctor`.
2. Желательно установить Git for Windows: тогда Claude Code выполняет команды через Git Bash.
3. Запуск: `cd C:\OSPanel\home\lifeOS.loc`, затем `claude`.
   Режим плана включается сочетанием `Shift+Tab` или при запуске `claude --permission-mode plan`.
4. Задача: `/lfs LFS-XXX` или просто `/lfs` — тогда Claude Code предложит следующую по очереди.

## Файлы настройки Claude Code и Codex

| Файл | Назначение |
|---|---|
| `CLAUDE.md` | Подключает `AGENTS.md` и добавляет только то, что касается Claude Code (скиллы, Read для картинок, plan mode) |
| `apps/web/CLAUDE.md` | Подключает `apps/web/AGENTS.md` (Next.js 16), загружается при работе в `apps/web` |
| `.claude/settings.json` | Разрешения: скрипты `pnpm`, чтение git, `git add`/`commit`/`push`/`switch` без вопросов; с вопросом — `pnpm add`, `git checkout`, `git stash`; запрет на чтение `.env`, `git reset --hard`, `git clean`, force push, push в `main` и удаление Docker volume |
| `.claude/skills/lfs/SKILL.md` | Команда `/lfs LFS-XXX`: выполнить задачу по процессу из `AGENTS.md` |
| `.claude/skills/lfs-review/SKILL.md` | Команда `/lfs-review LFS-XXX`: ревью чужой работы без правок |
| `.agents/skills/lfs`, `lfs-auto`, `lfs-review` | Команды Codex `$lfs`, `$lfs-auto`, `$lfs-review`: обёртки над процедурами из `.claude/skills/`; `agents/openai.yaml` — название в списке и запрет самозапуска |

Личные настройки, которые не должны попасть в git, кладутся в `.claude/settings.local.json`.
