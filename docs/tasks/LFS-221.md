# LFS-221 — Открытая регистрация

**Этап:** 2 — LifeOS Core (вставка в очередь после LFS-220 по запросу владельца 2026-11-21)
**Зависимости:** LFS-201 (Better Auth, allowlist), [ADR-005](../adr/005-auth.md)
**Макеты:** отдельного макета нет; `16-settings.png` — строка под «Изменить пароль»
**Цель:** зарегистрироваться может любой человек, а не только адреса из `AUTH_SIGNUP_ALLOWLIST`. Закрытый режим
остаётся и включается одной переменной.

## Решения владельца · 2026-11-21
1. «Сделай регистрацию свободной для всех»: на `/auth/sign-up` email вне списка получал «Регистрация закрыта».
2. Из трёх вариантов (переключатель в env, удалить allowlist совсем, только дописать свой email в `.env`) выбран
   рекомендованный: переключатель `AUTH_SIGNUP_MODE=open|allowlist`, по умолчанию `open`. Тексты страниц входа,
   регистрации и Настроек зависят от режима. Риски (нет подтверждения email, 422 раскрывает занятый адрес) были
   названы в вопросе.
3. Ветка `lfs-221-open-signup` создана от `lfs-220-first-login-popup`: LFS-220 ещё не влита в `main`.

## Результат LFS-221 · 2026-11-21

Ветка `lfs-221-open-signup` от `lfs-220-first-login-popup` (`4e397df`). Миграций нет. Решение —
[дополнение LFS-221 к ADR-005](../adr/005-auth.md#дополнение-lfs-221--2026-11-21).

### Что сделано

- **Env** (`@lifeos/config`): `AUTH_SIGNUP_MODE` — `open` (по умолчанию) или `allowlist`; другое значение даёт ошибку
  «AUTH_SIGNUP_MODE must be open or allowlist.» без самого значения. `AUTH_SIGNUP_ALLOWLIST` не изменился и читается
  только в режиме `allowlist`.
- **Домен**: `createOpenSignupPolicy()` пускает любой непустой email; у `SignupPolicy` появилось поле `mode`.
  `createSignupPolicy(emails)` работает как в LFS-201.
- **Web**: `server/auth` собирает политику один раз на процесс и отдаёт её Better Auth. Проверка по-прежнему в
  `user.validateUserInfo`, то есть на сервере. `getSignupMode()` — только для текстов страниц:
  - `/auth/sign-in`: «Зарегистрироваться» (в `allowlist` — «Регистрация по приглашению»);
  - `/auth/sign-up`: «Создайте аккаунт, чтобы вести цели и следить за прогрессом.» (в `allowlist` — прежний текст);
  - `/settings`: строка о закрытой регистрации показывается только в `allowlist`, текст исправлен на точный
    («новые аккаунты создаются только для адресов из списка доступа»: вход список не ограничивает).
- **Окружение и скрипты**: `.env.example` и `pnpm db:env` пишут `AUTH_SIGNUP_MODE=open`; `turbo.json` пропускает
  переменную в `dev`; UI-fixture явно `open`, build smoke явно `allowlist` с пустым списком, как раньше.
- **Тесты**: env (default, `allowlist`, отказ без эха значения); открытая политика; PostgreSQL integration — в `open`
  email вне списка регистрируется, повтор того же email даёт 422 без cookie, вход работает; e2e регистрации через
  форму на 1280 и 390.
