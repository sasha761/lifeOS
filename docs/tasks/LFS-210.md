### Реализация

- `activity_events`: требуемые поля плюс parent `goal_id`; compound FK
  `(user_id,domain_key,goal_id)` гарантирует владельца/сферу. Schema version 1,
  6 типов событий, 5 значений source. Реальный writer разрешает только web/manual.
- Strict contracts для goal/measurement before/after; measurement CRUD/таблица
  не вводились. Payload исключает title/description/custom labels, owner/email,
  password/session, raw body и response. Metadata changes — whitelist changed_fields.
- `GoalsService` принимает обязательный `GoalsUnitOfWork`, write-команды —
  отдельный server context с ключом. Domain callback формирует факт изменения;
  DB запускает одну Drizzle transaction с goals repository и typed writer.
  `ActivityEventWriter` требует `LifeosTransaction`, не root database.
- Узкие `goal_command_receipts` хранят только owner/key, SHA-256 запроса,
  operation/source/goal/domain/time. No-op edit и повтор archive записывают
  receipt без фиктивного event и без изменения resource timestamp.
- Scope ключа: пользователь + ключ для всех команд целей. Нормализованные
  operation/target/source/input сравниваются по hash. Изменённая нагрузка —
  CONFLICT, разные пользователи независимы. Replay возвращает актуальную ту же
  цель без повторного эффекта, не сохранённый старый HTTP response. Rollback
  освобождает ключ; lifetime receipt — до удаления владельца/цели.
- Transaction advisory key lock сериализует повторы, SELECT FOR UPDATE —
  разные команды одной цели. Before snapshot берётся после блокировки;
  clock_timestamp предотвращает время мутации до ожидания конкурента.
- Reader фильтруется по Actor, выдаёт максимум 100 событий по цели с
  детерминированным time/id порядком. Репозитории не имеют event update/delete.
  Runtime dependencies/стек не менялись, DB импортирует domain только как типы.
  Очередь/worker остаются прежними; event sourcing и проекции не вводились.

### Миграция и сохранность

`0004_activity_events.sql`, journal entry 5, snapshot 0004. Добавлены две таблицы,
индексы owner/time и owner/key, compound FK и поддерживающий UNIQUE goals.
В новом SQL UNIQUE перемещён перед зависимыми FK (порядок Kit был обратным),
FK не квалифицированы public для изолированных schemas, как в прошлых задачах.
Повторная генерация не находит изменений. История 0000–0003 не редактировалась.

Миграция применена к test DB и локальной main DB: journal main 4 → 5,
activity_events/receipts созданы пустыми, старые counts user/session/account/
verification/fixture/goals и число объектов pg-boss сохранены. Backfill
вымышленных событий старых целей отсутствует. SHA-256 прежних SQL проверен.
Откат схемы — новой forward-миграцией, без удаления applied history (ADR-008).
