# LFS-209 — E2E, security и приёмка Stage 2

**Этап:** 2 — LifeOS Core  
**Зависимости:** LFS-201, LFS-202, LFS-203, LFS-204, LFS-205, LFS-206, LFS-207, LFS-208, LFS-210, LFS-211, LFS-212  
**Цель:** Зафиксировать работающий первый мультидоменный LifeOS Core без регрессий Foundation.

## Область изменений
- `apps/web` — Playwright flows и тестовые фикстуры
- `packages/domain`, `packages/db` — недостающие tests
- `docs/tasks/STAGE-02-ACCEPTANCE.md` — результат приёмки

## Задание Codex
- [ ] Реализуй/дополни E2E для login → goal created → measurement saved → dashboard updated → edit/delete measurement → logout.
- [ ] Проверь все 6 доменов, пустые состояния, валютную и долг-формулы, backdated measurements, отсутствие measurement.
- [ ] Создай два тестовых пользователя и проверь попытки прочитать/записать чужой goal/measurement, а также URL/API без сессии.
- [ ] Проверь replay/idempotency всех повторяемых операций, audit rollback, невозможность получить user_id из request-body вместо сессии.
- [ ] Проверь миграции на чистой БД и Upgrade без удаления Stage 1 данных; убедись, что worker/pg-boss тесты Foundation проходят.
- [ ] Задокументируй результат acceptance checklist, известные ограничения и решение о переходе к Stage 3.
- [ ] Удали любые фиктивные данные/псевдо-progression из публичного Dashboard (тестовые фикстуры допускаются только в test).

## Acceptance criteria
- [ ] Playwright E2E; unit/domain; DB integration; regressions stage1.
- [ ] `pnpm lint`, `pnpm typecheck`, `pnpm test`, `pnpm build` и проверка `git status --short`.

## Проверки / тесты
- [ ] Основной сценарий работает в браузере без SQL/manual DB.
- [ ] В каждом запросе ownership корректен; гости изолированы.
- [ ] Суммы/значения и проценты совпадают с DB.
- [ ] CI green; Stage 1 не сломан.
- [ ] Документ принятия/ограничений заполнен.

## Вне scope
Telegram, AI, полные функции финансов, уроки, Kanban, будущий SaaS. Старт Stage 3 — только после подтверждения результатов.

## Общие правила для Codex

1. Работай **только в репозитории** `C:\OSPanel\home\lifeOS.loc`; сперва проверь `git status`, `AGENTS.md`, `docs/reference/LifeOS_Master_Plan_v0.4.md`, существующие ADR, пакеты и миграции. Если структура отличается, адаптируй реализацию и сообщи об отличиях; не затирай чужие изменения.
2. Следуй утверждённому стеку из `docs/adr/001-stack.md` и текущего `pnpm-lock.yaml`: Next.js/React/TypeScript strict, PostgreSQL, Drizzle, Better Auth, Zod. **Не** внедряй Laravel, Vue/Nuxt, Redis, Telegram, AI, FSRS, биллинг или дополнительные SaaS-абстракции.
3. Бизнес-правила — в `packages/domain`; DTO/Zod — в `packages/contracts`; SQL-таблицы/миграции/репозитории — в `packages/db`; Next.js Route Handlers и UI — только адаптеры. Если реальные границы пакетов отличаются, сохраняй их архитектурный смысл.
4. Сфера MVP: `languages`, `finance`, `work`, `projects`, `skills`, `health`. В Stage 2 все они поддерживают **только общие ручные цели**, без специализированных трекеров. Нет выдуманных процентов, данных банка или уровня компетенции.
5. Перед кодом перечисли затрагиваемые файлы и риски. Не изменяй ADR/спецификацию молча; несовместимость или необходимую миграцию опиши отдельно.
6. В конце выполни релевантные проверки, приведи **реальные** результаты, diff и список оставшихся ограничений. Не переходи к следующей задаче без разрешения.
