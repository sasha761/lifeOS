## Общий принцип

Сейчас каждая цель обязана быть числовой: у неё есть единица, старт и цель ([ADR-007](../adr/007-goals.md)). Поэтому мастер на каждом
шаге спрашивает «сколько штук / откликов / этапов», а это топорно. Новое правило:

- **Число спрашиваем, только если без него цель теряет смысл:** сумма долга, сколько накопить, вес, уровень языка.
- Всё остальное — выбор из вариантов, короткий текст или необязательные поля.
- Если у цели нет естественного числа («найти работу», «пройти курс», «запустить проект», свой текст), это **цель
  без измерений**: статус «В процессе → Достигнута», процента нет.
- Измерение — событие, которое произошло, а не переписанный итог: «внёс платёж 800 $». Остаток и процент система
  считает сама.

## Решения владельца · 2026-11-22

1. Цели без измерений: статус «В процессе → Достигнута», достигнутой цель отмечает сам человек.
2. Дата начала нужна (у курса и вообще у цели), вместе со сроком окончания.
3. Взнос — сумма, которую человек направил на цель: получил зарплату или деньги за фриланс и внёс их. Остаток и
   процент система считает сама. Уже созданные цели переносить не нужно: владелец пересоздаст свои.
4. Несколько вариантов в одном вопросе — пока только в Финансах.
5. Часовой пояс уходит из мастера, его меняют в Настройках.
6. Ритм удаляется полностью, вместе с колонкой `checkin_rhythm` и сохранёнными значениями.
7. Для изменённых экранов делаются новые макеты, до кода.
8. Числовые уточнения в «Работе» и «Навыках» упрощаются.

| 4.1 | `/settings` | Блок «Ритм отметок» удалить | LFS-222 |

Почему 60%. Сейчас измерение — это текущий остаток: current — последнее измерение ([ADR-009](../adr/009-goal-measurements.md)). Цель «уменьшить» считается
как `(старт − текущее) / (старт − цель)` ([ADR-010](../adr/010-goals-api-progress.md)), то есть (2000 − 800) / 2000 = 60%: система поняла «осталось 800».
Человек имел в виду «выплатил 800», значит осталось 1 200, то есть 40%.
