# LFS-203 — Реестр жизненных сфер LifeOS

**Этап:** 2 — LifeOS Core  
**Зависимости:** LFS-202  
**Цель:** Зафиксировать ядро мультидоменной платформы без универсальных таблиц и плагинной системы.

## Область изменений
- `packages/domain/core/domains` — typed registry + metadata
- `packages/contracts` — domainKey schema/type
- `apps/web` — navigation/empty states
- unit tests

## Задание Codex
- [x] Создай кодовый реестр из шести `domain_key`: `languages`, `finance`, `work`, `projects`, `skills`, `health` с локализуемым названием, описанием, статусом и стабильным URL.
- [x] UI-specific иконки должны маппиться в Web; доменный пакет не импортирует React/Next.js.
- [x] Введи типизированную валидацию `domain_key` в Zod, единый источник истины для UI и API; строки вне реестра отклоняются.
- [x] Раздели `available` (общие ручные цели) и `specializedAvailable` (false для Stage 2). Не показывай будущие интеграции как работающие.
- [x] Реализуй страницы сфер с честным empty state, ссылкой на создание общей цели или заглушкой «специализированный модуль позже».

## Acceptance criteria
- [x] Unit tests registry, key validation; проверить `/domains`-подобные маршруты в текущем роутинге (не создавать лишних).
- [x] Проверить мобильный layout, линтер, типы и сборку.

## Проверки / тесты
- [x] Все 6 сфер отображаются, названия и ключи совпадают с API.
- [x] Нельзя создать произвольный седьмой ключ без изменения реестра.
- [x] Ни фиктивного процента, ни выдуманного банковского баланса, ни искусственного CEFR.
- [x] Никакой таблицы `domains`.

## Вне scope
Полноценные finance/work/projects/skills/health модели, коннекторы, AI, billing.

## Общие правила для Codex

1. Работай **только в репозитории** `C:\OSPanel\home\lifeOS.loc`; сперва проверь `git status`, `AGENTS.md`, `docs/reference/LifeOS_Master_Plan_v0.4.md`, существующие ADR, пакеты и миграции. Если структура отличается, адаптируй реализацию и сообщи об отличиях; не затирай чужие изменения.
2. Следуй утверждённому стеку из `docs/adr/001-stack.md` и текущего `pnpm-lock.yaml`: Next.js/React/TypeScript strict, PostgreSQL, Drizzle, Better Auth, Zod. **Не** внедряй Laravel, Vue/Nuxt, Redis, Telegram, AI, FSRS, биллинг или дополнительные SaaS-абстракции.
3. Бизнес-правила — в `packages/domain`; DTO/Zod — в `packages/contracts`; SQL-таблицы/миграции/репозитории — в `packages/db`; Next.js Route Handlers и UI — только адаптеры. Если реальные границы пакетов отличаются, сохраняй их архитектурный смысл.
4. Сфера MVP: `languages`, `finance`, `work`, `projects`, `skills`, `health`. В Stage 2 все они поддерживают **только общие ручные цели**, без специализированных трекеров. Нет выдуманных процентов, данных банка или уровня компетенции.
5. Перед кодом перечисли затрагиваемые файлы и риски. Не изменяй ADR/спецификацию молча; несовместимость или необходимую миграцию опиши отдельно.
6. В конце выполни релевантные проверки, приведи **реальные** результаты, diff и список оставшихся ограничений. Не переходи к следующей задаче без разрешения.

### Реализация и границы

- `packages/contracts/src/domains.ts`: замороженный `DOMAIN_KEYS`,
  `domainKeySchema`, `DomainKey`. Это единственный список ключей UI и будущих
  API DTO с `domain_key`. Схема точная, без trim/изменения регистра.
- `packages/domain/src/core/domains.ts`: `LIFE_DOMAINS`, `findLifeDomain(unknown)`;
  локализуемые `name`/`description` (`ru`, `en`), `status`, `available`,
  `specializedAvailable`, стабильный URL. Реестр и вложенные переводы
  заморожены. Реальное расположение соответствует существующему `src/core/`.
- `available: true` / `status: available` означают поддержку общей модели
  ручных целей. Редактора целей ещё нет (LFS-208), что прямо написано на
  страницах. `specializedAvailable: false` во всех шести сферах; показатели,
  банковские данные, CEFR и внешние интеграции не имитируются.
- `apps/web/lib/domain-presentation.ts`: exhaustive mapping иконок/цветов;
  React/Next.js не импортируются в domain/contracts.
- Навигация и карточки главной используют общий реестр. Небольшой client
  `NavigationLink` задаёт `aria-current` по текущему URL; остальной UI — RSC.
- `app/(web)/domains/[domainKey]/page.tsx`: ровно шесть публичных страниц
  метаданных (`generateStaticParams`, `dynamicParams: false`), локализованная
  metadata и честные пустые состояния. Страницы не читают БД/сессию, личных
  данных нет. `/goals` сохраняет прежнюю защиту; ссылка не обещает создание.
  Обзор остаётся на `/`/`#areas`, лишняя страница `/domains` не добавлена.

Миграций, изменений схемы БД, таблицы `domains`, новых dependencies и
архитектурных решений нет; существующие ADR и Master Plan не изменялись.
