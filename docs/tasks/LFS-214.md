# LFS-214 — Постраничный журнал действий

**Этап:** 2 — LifeOS Core (доработка по рискам LFS-213, не блокирует Stage 3)
**Зависимости:** LFS-213 (`GET /api/v1/activity`); [ADR-008](../adr/008-transactional-audit.md); образец курсора — `GET /api/v1/goals` и
`GET /api/v1/goals/:goalId/measurements` (LFS-207, [contracts.md](../api/contracts.md))
**Цель:** вся история цели и сферы доступна: старые записи журнала подгружаются по курсору, а не обрезаются на 50.

## Почему

`GET /api/v1/activity` отдаёт не больше 50 новейших записей и не умеет продолжать выдачу. Панель цели показывает
10 записей, страница сферы — 5. Записи старше этих лимитов в интерфейсе недоступны. Пока целей и измерений мало,
это незаметно; через несколько месяцев ведения история обрезается.

## Область изменений
- `packages/contracts/src/activity.ts` — `cursor` в запросе, `nextCursor` в ответе
- `packages/db/src/repositories/activity-reader.ts` — keyset по `(occurred_at, id)` на существующих индексах
- `packages/domain/src/core/activity.ts`, `apps/web/server/activity.ts`
- `apps/web/components/goals/goal-detail.tsx` («История изменений»), `components/domains/domain-personal.tsx`
- тесты, `docs/api/contracts.md`

## Задание
- [ ] Курсор устроен так же, как у целей и измерений: непрозрачный token, привязан к фильтру (`domain_key` или
  `goal_id`), SQL всегда ограничен session Actor даже при изменённом token.
- [ ] Записи с одинаковым `occurred_at` не теряются и не дублируются на границе страниц (порядок
  `occurred_at desc, id desc`).
- [ ] Ответ — `{ items, nextCursor }`; `nextCursor: null` на последней странице. Лимит по-прежнему 1–50.
- [ ] Курсор от другого фильтра или испорченный token → 400 с безопасной ошибкой.
- [ ] UI: «Показать ещё» под «Историей изменений» цели и под «Последними действиями в сфере». Новые записи
  добавляются в конец списка, фокус остаётся на кнопке, при ошибке видно сообщение и кнопку повтора.
- [ ] Dashboard не меняется: его 5 записей приходят из read model.

## Acceptance criteria
- [ ] Тесты контракта (token, фильтр, лимит), PostgreSQL integration: три страницы подряд без потерь и дублей,
  граница с равным `occurred_at`, чужой пользователь с чужим token получает пусто, а не чужие записи.
- [ ] e2e: в панели цели с историей длиннее страницы «Показать ещё» догружает записи; клавиатура работает.
- [ ] `pnpm verify`, `pnpm test:ui` зелёные; миграций нет. Если план запросов требует индекса, согласовать в плане.

## Вне scope
Отдельная страница журнала, фильтры по типу события и датам, экспорт истории (Stage 8).
