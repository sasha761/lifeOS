# LFS-202 — Профиль пользователя, locale/timezone, ownership

**Этап:** 2 — LifeOS Core  
**Зависимости:** LFS-201  
**Цель:** Сделать данные и права пользователя корректными до появления целей.

## Область изменений
- `packages/db` — расширение Better Auth `user` и миграция
- `packages/domain/core` — current-user context, ownership helpers
- `apps/web` — профиль, server-side auth checks
- тесты cross-user access

## Задание Codex
- [ ] Добавь `timezone` (валидный IANA timezone) и `locale` (корректный BCP 47) к `user` с безопасными default/migration.
- [ ] Определи единый способ получения `actor.userId` из проверенной серверной сессии для Route Handlers и domain-команд. Запрети передачу доверенного user_id из публичных request body.
- [ ] Определи паттерн ownership для ресурсов: выборки/мутации фильтруются по user_id либо по связи с владельцем; отсутствие чужого ресурса — согласованный 404/403 без раскрытия данных.
- [ ] Реализуй чтение/изменение собственного timezone/locale с Zod validation; отображай выбранный часовой пояс, сохраняй даты в UTC.
- [ ] Сделай reusable негативные тесты с **двумя** пользователями и документируй способ их применения будущими репозиториями.

## Acceptance criteria
- [ ] Unit tests timezone/locale; integration cross-user 401/403/404; migrations upgrade/rollback strategy.
- [ ] lint/typecheck/test/build; проверить сохранение prefs после повторного входа.

## Проверки / тесты
- [ ] Фальшивый `userId` в запросе не меняет actor; нет сквозных вызовов с непроверенным actor.
- [ ] Локаль/часовой пояс валидируются и сохраняются только для владельца.
- [ ] Чужие профиль/сессия недоступны через API.
- [ ] Регрессии LFS-201 не появились.

## Результат LFS-202 · 2026-11-15

Реализованы `user.timezone`/`user.locale`, единый actor из проверенной сессии и
правило ownership для всех будущих core repositories. Решения, альтернативы и
стратегия миграции/отката — [ADR-006](../adr/006-actor-ownership.md).

- **Схема:** `packages/db/drizzle/0002_user_preferences.sql` — `timezone text NOT NULL DEFAULT 'UTC'`,
  `locale text NOT NULL DEFAULT 'ru'`, CHECK по длине. Только расширение; Better Auth колонки не знает,
  его конфигурация не менялась.
- **Actor:** branded `Actor` (`@lifeos/domain`) создаётся только `actorFromVerifiedSession`;
  Route Handlers — `requireApiActor()`, страницы — `requirePageSession()`.
- **Ownership:** SQL-фильтр `ownedBy(table.userId, actor, …)` (`@lifeos/db`) + `requireOwned()`;
  чужой, несуществующий и некорректный id — одинаковый 404 `NOT_FOUND`, никогда 403.
- **Preferences:** `GET/PATCH /api/v1/me/preferences` (strict DTO, `userId` в body → 400),
  страница `/settings` (UTC-время показывается в выбранном часовом поясе), часовой пояс на `/dashboard`.
- **Переиспользование:** `apps/web/tests/integration/support/auth-harness.ts` и
  `support/ownership-contract.ts` (`expectDomainOwnership`, `expectHttpOwnership`) —
  способ применения описан в ADR-006 и в комментарии модуля.

**Найдено и исправлено ручной проверкой.** В production-сборке после открытия
`/settings` невалидный PATCH отвечал 500 вместо 400: RSC-страница и Route
Handler — разные слои бандла со своими копиями `@lifeos/domain`, а сервис был
закэширован на `globalThis`. Теперь сервисы кэшируются на уровне модуля, маппер
использует `isDomainError()` (бренд `Symbol.for`), есть регрессионные unit-тесты.

**Ограничения.** Список часовых поясов и валидатор зависят от ICU Node.js
(tz 2026e); браузер может отличаться — сервер авторитетен. Страницы с
preferences делают второй запрос к БД. Отдельной Origin-проверки для `/api/v1`
мутаций нет (PATCH требует CORS preflight, cookie `SameSite=Lax`). Hosted CI не
запускался. LFS-203 не начат.
