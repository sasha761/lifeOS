# LFS-220 — Попап первого входа и кнопка в Настройках

**Этап:** 2 — LifeOS Core (вставка в очередь после LFS-219, последняя перед Stage 3, по запросу владельца 2026-11-18)
**Зависимости:** LFS-218 (пример и его удаление), LFS-219 (мастер и `onboarding_state`), LFS-202 (Настройки);
[ONBOARDING](../reference/ui/ONBOARDING.md)
**Макеты:** `23-onb-start.png` (попап), `29-onb-mobile.png` (левый экран), `28-onb-example.png` (кнопка
«Пройти настройку вместо примера»), `30-onb-settings.png` (раздел в Настройках), `31-onb-reopen.png` (попап из
Настроек). Точные размеры — `docs/reference/ui/html/`.
**Цель:** пустой аккаунт сразу видит выбор: пример, вопросы или чистый лист. Тот же выбор открывается в любой
момент кнопкой в Настройках.

## Решения владельца · 2026-11-18
1. Попап показывается на `/dashboard` (сюда ведёт вход), если у пользователя нет ни одной цели, активной или
   архивной, и начальная настройка не завершена и не отклонена.
2. Варианты: «Настроить под себя» (рекомендуем) → мастер LFS-219; «Посмотреть на примере» → пример LFS-218;
   «Начать с чистого листа» → попап больше сам не появляется.
3. В Настройках аккаунта — раздел «Начальная настройка» с кнопкой, которая открывает **этот же попап**
   с выбором между примером и вопросами.

## Решения владельца · 2026-11-21
1. Ветка `lfs-220-first-login-popup` создана от `lfs-219-onboarding-wizard` (вариант «б»): код LFS-219 ещё не в `main`,
   PR #7 влит в `lfs-218-starter-pack`. Пока LFS-219 не в `main`, PR LFS-220 содержит и его коммиты.
2. План принят ответом «ок» без выбора вариантов, поэтому взяты рекомендованные:
   - **1а.** «Заполнить примером» и «Добавить пример» вызывают `POST /api/v1/starter-pack`, а сервер в той же транзакции
     ставит незавершённой настройке `completed` и `choice = example`. Отдельного `PATCH` для примера нет.
   - **2а.** N в «пройдена ДД.ММ.ГГГГ · N целей» — цели, данные пройденной настройкой и ещё оставшиеся в аккаунте: цели
     мастера или, если выбран пример, цели с меткой «Пример». При нуле показывается только дата.
3. Решения плана, которые владелец не оспорил:
   - «Ритм отметок» сохраняется кнопкой «Сохранить», как «Язык и время»;
   - пометки дизайнера на `31` («Если пример уже загружен…», «Это тот же попап…») не показываются;
   - колонка Настроек во всю ширину, как на `16` и `30`;
   - «Начать вопросы» в Настройках — ссылка на `/onboarding`, статус не меняет;
   - «Пройти настройку вместо примера» статус не меняет.

## Задание
- [x] Условие показа считается на сервере и приходит вместе с данными страницы, без отдельного клиентского запроса:
  нет целей и `status` равен `not_started` или `in_progress`. Аккаунт с целями (в том числе аккаунт владельца)
  попап сам не видит.
- [x] Попап `23`: диалог (`role="dialog"`, `aria-modal`, фокус внутри, Escape = «✕»), тексты и порядок как на макете.
  - «Начать настройку →» → `status = in_progress`, `choice = wizard`, переход на `/onboarding`;
  - «Заполнить примером» → `POST /api/v1/starter-pack`, затем `choice = example`, `status = completed`; попап
    закрывается, Кабинет показывает пример и баннер. При ошибке — сообщение в попапе, он не закрывается;
  - «Начать с чистого листа» → `status = dismissed`, `choice = blank`;
  - «✕» закрывает до следующего входа (в пределах сессии браузера), статус не меняется.
- [x] Мастер начат и не завершён: основная кнопка попапа — «Продолжить настройку» (с того шага, где остановились).
- [x] Мобильный вид: нижняя панель по `29` (левый экран), кнопки на всю ширину.
- [x] Настройки (`30`): пункт «Начальная настройка» в меню разделов и раздел на странице:
  - статус: «Не пройдена», «Пройдена ДД.ММ.ГГГГ · N целей» или «Отклонена»;
  - кнопка «Открыть начальную настройку» — открывает попап;
  - «Ритм отметок» — выбор, сохраняет `checkin_rhythm`;
  - «Сферы в фокусе» — только просмотр;
  - «Примерные цели» — число и «Удалить все примеры» (команда LFS-218), если примеры есть, иначе «нет».
- [x] Попап из Настроек (`31`): тот же компонент в ручном режиме, открывается всегда, при любом числе целей и статусе.
  Заголовок «Что добавить в аккаунт?», «Ваши N целей останутся как есть». «Добавить пример» неактивна с подписью
  «Пример уже в аккаунте», если есть примерные цели. «Начать вопросы →» ведёт на `/onboarding` с прошлыми ответами
  как черновиком. Вместо «Начать с чистого листа» — «Закрыть».
- [x] Баннер примера (`28`): кнопка «Пройти настройку вместо примера» → подтверждение «Удалим N примерных целей
  и откроем вопросы» → `DELETE /api/v1/starter-pack` → `/onboarding`.
- [x] Статус хранится только на сервере; `sessionStorage` допускается только для «✕».

### Что сделано

- **Контракты** (`onboarding.ts`, `dashboard.ts`):
  - тело `PATCH /api/v1/onboarding` — строго один из трёх вариантов: `{ in_progress, wizard }`, `{ dismissed, blank }`,
    `{ checkin_rhythm }`;
  - в `OnboardingState` добавлены `checkin_rhythm`, `focus_domains` и `goals { total, onboarding, examples }`;
  - в Dashboard добавлено `onboarding { status, show_start }`: контракт отклоняет `show_start` при целях в аккаунте или
    при неподходящем статусе;
  - схема `focusDomainsSchema` теперь общая для онбординга и Dashboard.
- **Домен**:
  - `showsStartDialog` — правило показа попапа;
  - `OnboardingService.update` — выбор в попапе (из `completed` — 409) или ритм;
  - `get` и ответы `PUT`/`PATCH` читают одним снимком состояние, профиль и счётчики;
  - загрузка примера в своей транзакции вызывает `completeWithExample`;
  - Dashboard отдаёт `onboarding`.
- **БД**:
  - `choose` и `completeWithExample` — условный upsert `ON CONFLICT … DO UPDATE … WHERE status <> 'completed'`;
  - `setCheckinRhythm` пишет только в строку владельца;
  - `createOnboardingOverviewRepository`: два запроса владельца в снимке READ ONLY REPEATABLE READ;
  - Dashboard читает статус тем же запросом профиля (LEFT JOIN), число запросов не выросло.
- **HTTP**: `PATCH /api/v1/onboarding` — сессия, Origin, без query. Build smoke проверяет 401.
- **UI**:
  - `components/ui/modal-dialog.tsx` — механика нативного `<dialog>` (showModal, фокус внутри и возврат, Escape, Tab)
    вынесена из `Modal`; `Modal` теперь построен на ней;
  - `components/onboarding/start-dialog.tsx` — один компонент для Кабинета и Настроек:
    - от 640 px окно шириной 860 px с двумя карточками, на телефоне нижняя панель;
    - при начатом мастере «Продолжить настройку»;
    - на 409 понятные сообщения;
  - `components/onboarding/examples-confirm.tsx` — подтверждение удаления примеров вынесено из Кабинета и используется
    в двух вариантах: «Удалить все примеры?» и «Пройти настройку вместо примера?»;
  - Кабинет:
    - попап по `show_start`;
    - «✕» и Escape запоминаются в `sessionStorage` (`lib/start-dialog-session.ts`), «Выйти» их забывает;
    - на баннере кнопка «Пройти настройку вместо примера»;
  - Настройки:
    - пункт меню и раздел «Начальная настройка»: статус, кнопка открытия попапа, ритм с «Сохранить», сферы в фокусе,
      примерные цели с «Удалить все примеры»;
    - в `SectionCard` добавлен `titleAddon` для чипа рядом с заголовком;
    - колонка разделов во всю ширину.
- **Тесты**:
  - contracts: +3;
  - domain: `dashboard` +1, `onboarding` +5, `starter-pack` +1;
  - web unit: `setupStatus` +1;
  - PostgreSQL integration `onboarding.test.ts`: +7 — переходы, 409 из `completed`, изоляция второго пользователя, ритм
    и счётчики, пример завершает настройку, `show_start`, HTTP;

- **Фикстура UI**: 4 новых пустых аккаунта (`start*`, `startExample*`). `pnpm ui:shots`: снимки `dashboard-start`,

### Ограничения

- «✕» хранится в `sessionStorage` вкладки: в новой вкладке попап появится снова. Если сменить пользователя в той же
  вкладке без «Выйти», флаг доживёт до её закрытия.
- После «Пройти настройку вместо примера» статус остаётся «пройдена». Если выйти из мастера без сохранения, Кабинет
  будет пуст и попап сам не появится; вернуться можно через Настройки.
- «Начать вопросы» в Настройках статус не меняет: начатой настройка станет после «Сохранить и выйти».
- Код LFS-219 ещё не в `main`: PR LFS-220 в `main` будет содержать и коммиты LFS-219.
