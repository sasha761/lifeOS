# LFS-104 — PostgreSQL, Drizzle и миграции

**Зависимости:** LFS-102; предпочтительно LFS-103 завершён  
**Цель:** воспроизводимая локальная БД и управляемые SQL-миграции, без пользовательских таблиц Этапа 2.

## Задание Codex

1. Добавь **Docker Compose для локального PostgreSQL** (в `infra/docker` или на корне с ясной документацией). Храни пароль в локальном `.env`; в `.env.example` только dev-пример/placeholder, без реальных секретов. Volume постоянный, healthcheck настроен.
2. В `packages/db` создай подключение к PostgreSQL через драйвер, **совместимый одновременно с Drizzle и pg-boss/transaction adapter**. Проверь выбор драйвера по официальным docs, укажи его в ADR.
3. Добавь Drizzle schema organization, `drizzle.config.ts`, автоматическую генерацию SQL-миграций и команду применения миграций через `drizzle-kit`/документированный migration runner.
4. Для Этапа 1 используй **только техническую test-fixture таблицу**, если нужно продемонстрировать миграцию; не создавать `users`, `goals`, `activity_events`. Имена fixture должны явно указывать, что они не часть доменной схемы. Допустимо создать тестовую миграцию и описать последующее удаление.
5. Подготовь команды `db:up`, `db:down` (без `-v` по умолчанию), `db:generate`, `db:migrate`, `db:status`/проверку подключения и интеграционный smoke-тест миграции в чистой БД.
6. Документируй `DATABASE_URL` для Web, worker и тестов: отдельная тестовая БД/схема, чтобы CI не удалял пользовательские данные.

## Acceptance criteria

- [ ] PostgreSQL поднимается и проходит healthcheck.
- [ ] Миграции можно применить на **чистой БД** без ручных SQL-команд и повторный запуск не ломает схему.
- [ ] `packages/db` импортируется из Web/worker без зависимости от Next.js.
- [ ] В Git нет действующих паролей и `.env`.
- [ ] Нет пользовательских таблиц и миграций следующих этапов.

## Проверки

Команды Docker Compose; `pnpm db:migrate` (или эквивалент из package scripts); проверка schema и интеграционный тест с **отдельной тестовой БД**. Если Docker недоступен — записать причину и ручной сценарий проверки.

## Вне scope

Better Auth database tables, CRUD целей, `activity_events`, Redis, отдельная брокер-очередь.
