# LFS-109 — Архитектурная документация и handoff для Codex

**Зависимости:** LFS-101–108  
**Цель:** поддерживаемый проект, который следующий разработчик/Codex может запускать и развивать без догадок.

## Задание Codex

1. Прочитай реальный код после LFS-101–108; документация должна **описывать действующее решение**, а не идеальную несуществующую систему.
2. Создай `docs/architecture/system.md`: диаграмма Web/API → application/domain → DB/worker; границы пакетов, импортируемые зависимости, Node execution model, location of env/config, пути `/` и `/telegram`.
3. Создай `docs/architecture/database-schema.md`: какие технические таблицы уже существуют и что **планируется в Этапе 2** (Better Auth, `goals`, `goal_measurements`, `activity_events`) — строго разделить реализованное и будущее.
4. Создай `docs/api/contracts.md`: JSON envelope, error codes, Zod, request/correlation ID и `GET /api/health`, без заявлений о готовых целях/Auth APIs.
5. Создай `docs/architecture/worker.md`: регистрация job, producer/consumer lifecycle, транзакционный enqueue, idempotency, retries, graceful shutdown; ссылки на ADR-002 и интеграционные тесты.
6. Дополни ADR: stack (LFS-102), queue atomicity (LFS-107), маршрутизация Next.js, выбор границ монолита. Используй краткий ADR-шаблон.
7. Обнови корневой README: установка Docker Desktop/WSL2 для Windows 11 или Linux, `pnpm`, `.env.example`, запуск базы/миграций/Web/worker, тесты и типичные ошибки. Дай **точные реальные** команды из package scripts.
8. Создай `docs/DEVELOPMENT_WORKFLOW.md`: Git branches/commits, один LFS-ID на PR, review/diff/checklist, следующий Этап 2, запрет scope creep.
9. Проведи финальный self-audit Definition of Done Этапа 1, зафиксируй PASS/FAIL/NOT RUN по всем критериям в `docs/tasks/STAGE-01-ACCEPTANCE.md`.

## Acceptance criteria

- [x] Реальные команды локальной установки воспроизводимы по README — текущий verify PASS; невозможность полного remote-clone walkthrough документирована ниже.
- [x] Структура модулей и таблиц соответствует коду и миграциям.
- [x] Риски транзакционности, ограничения текущего окружения и deferred features не скрыты.
- [x] Есть статусы CI/test/build с конкретным evidence.
- [x] Stage 2 явно отделён: **не** реализован при выполнении LFS-109.

## Проверки

Сверка путей и скриптов с файловой системой; `pnpm verify` и health-check при наличии окружения; `git diff --check`; вручную пройти инструкции README в свежем clone или задокументировать невозможность.

## Вне scope

Реализация auth/целей/доменов/Telegram/AI: все они начинаются в следующих этапах.
