# LFS-225 — Статусы целей, цели без измерений и дата начала

**Этап:** 2 — LifeOS Core (вставка после LFS-224, перед Stage 3, по замечаниям владельца 2026-11-21,
[STAGE-02-FEEDBACK](STAGE-02-FEEDBACK.md), п. 1.3–1.7, 2.3)
**Зависимости:** LFS-205–208, LFS-216, LFS-217; [ADR-007](../adr/007-goals.md), [ADR-010](../adr/010-goals-api-progress.md); макеты `32`, `33`, `36`, `44` (LFS-223)
**Цель:** появляется вид цели без чисел: статус «В процессе → Достигнута», отметку ставит сам человек. У любой цели
появляется необязательная дата начала.

## Почему

Не у каждой цели есть естественное число: «найти работу», «пройти курс», «запустить проект», цель своими словами.
Сейчас ADR-007 требует единицу, старт и цель, поэтому мастер заставляет придумать «20 откликов» или «8 этапов». Это
противоречит правилу «никаких выдуманных метрик» и путает нового пользователя.

## Решения владельца · 2026-11-22

1. Цель без измерений имеет статус «В процессе → Достигнута», достигнутой её отмечает сам человек.
2. Дата начала нужна вместе со сроком окончания.

## Область изменений

- `packages/contracts/src/goals.ts` и связанные DTO (`GoalDetails`, `progress`, события)
- `packages/domain/src/core/goals.ts`, расчёт прогресса, команды измерений (запрет для такой цели)
- `packages/db`: схема `goals`, CHECK, репозитории, новая миграция
- `apps/web`: `goals-browser.tsx`, `goal-detail.tsx`, `goal-form.tsx` (правка), Dashboard и страница сферы, журнал действий
- Новый ADR (следующий свободный номер), строки в индексе ADR; `docs/api/contracts.md`, `database-schema.md`

## Задание

- [ ] Вид цели: числовая (как сейчас) и без измерений. Название поля и значений фиксирует ADR. У цели без
  измерений `unit`, `unit_label`, `baseline`, `target`, `direction` пустые; у числовой они обязательны, как сейчас.
  Правило держат контракт, домен и SQL CHECK. Вид после создания не меняется.
- [ ] Статус любой активной цели, числовой и без измерений (решения владельца 10 и 11 в LFS-223, для доски
  LFS-229): «Запланирована», «В процессе», «На паузе», «Достигнута». Переход между любыми двумя — ручная команда,
  время смены сохраняется («отмечена 15.11.2026», «на паузе с 10.11.2026»). Новая цель с датой начала в будущем
  получает «Запланирована», остальные — «В процессе»; дальше система статус сама не меняет, автоматической отметки
  «Достигнута» по 100% нет, процент числовой цели не зависит от статуса. Измерения можно добавлять в любом статусе,
  кроме архива. Архив — отдельный терминальный статус, как сейчас (ADR-007). Смена статуса — команда с
  `Idempotency-Key` и событием журнала, как остальные команды целей (ADR-008). В панели: у цели без измерений
  главная кнопка — «✓ Отметить достигнутой» или «↺ Вернуть в работу», у любой цели все переходы — в меню «⋯»
  («Начать», «Поставить на паузу», «Продолжить», «Отметить достигнутой», «Вернуть в работу»).
- [ ] Цели без измерений нельзя добавить измерение: API отвечает 409 или 400 (выбрать в ADR), SQL не даёт вставить
  строку.
- [ ] Дата начала — необязательное поле любой цели. Если заданы обе даты, начало не позже срока. Как дата
  переводится в момент в поясе пользователя — по образцу срока (ADR-010), записать в ADR.
- [ ] Прогресс цели без измерений: процента нет, статус и объяснение — по контракту из ADR («В процессе» /
  «Достигнута»), а не «Недостаточно данных».
- [ ] `/goals` (макеты 32, 36): у строки цели без измерений нет полосы прогресса; справа чип «В процессе» или
  «✓ Достигнута», под названием «сфера · с <начало> · до <срок>» или «сфера · отмечена <дата>». Панель «В процессе»
  (макет 36): крупно «В процессе», «с <начало> · N дней до срока», пояснение «Процента нет…», главная кнопка
  «✓ Отметить достигнутой», описание, «Как считается ›» и «История изменений ›». Панель «Достигнута» (отдельного
  макета нет, решение владельца): крупно зелёным «✓ Достигнута», «отмечена <дата>» и «◉ ручная отметка», пояснение
  «Цель снова станет «В процессе», если вернуть её в работу. Отметка останется в истории.», вторичная кнопка
  «↺ Вернуть в работу» на месте главной, описание и те же ссылки. Достигнутая цель остаётся во вкладке «Активные»
  (решение владельца, LFS-223); на доске это колонка «Достигнуты» (LFS-229). У числовой цели в статусе
  «Запланирована» или «На паузе» статус — чип рядом с названием (макет 32); в панели — чип рядом с названием цели.
- [ ] Dashboard и страница сферы показывают такие цели без процента: число в процессе и достигнутых. Общий процент
  сферы не придумывается.
- [ ] Правка (LFS-217): у цели без измерений меняются название, описание, дата начала и срок.
- [ ] Создать цель без измерений через интерфейс можно будет в LFS-227 (мастер) и LFS-228 (новая цель). Здесь —
  API, отображение и тесты через API.

## Acceptance criteria

- [ ] Тесты контракта: цель без измерений без чисел, с числами — 400; дата начала позже срока — 400.
- [ ] Integration: создание (статус по дате начала), все переходы статусов у обоих видов целей, архив, удаление,
  отказ в измерении, SQL guard в обход сервиса, чужой
  пользователь, повтор команд с тем же ключом; миграция на чистой схеме и обновление с предыдущей.
- [ ] e2e: цель без измерений (создана через API) в списке и панели, отметка «Достигнута» и возврат.
- [ ] `pnpm verify`, `pnpm test:ui`, `pnpm build`, `pnpm test:build` зелёные; `pnpm ui:shots` и таблица отличий против
  макетов 32 и 36.

## Вне scope

Чек-листы и этапы (модуль Проекты, этап 9). Автоматическая отметка «Достигнута» у числовых целей. Перевод числовой цели
в цель без измерений и обратно. Пример целей (LFS-218) не меняется.
