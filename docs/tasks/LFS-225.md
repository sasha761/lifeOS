# LFS-225 — Статусы целей, цели без измерений и дата начала

**Этап:** 2 — LifeOS Core (вставка после LFS-224, перед Stage 3, по замечаниям владельца 2026-11-21,
[STAGE-02-FEEDBACK](STAGE-02-FEEDBACK.md), п. 1.3–1.7, 2.3)
**Зависимости:** LFS-205–208, LFS-216, LFS-217; [ADR-007](../adr/007-goals.md), [ADR-010](../adr/010-goals-api-progress.md); макеты `32`, `33`, `36`, `44` (LFS-223)
**Цель:** появляется вид цели без чисел: статус «В процессе → Достигнута», отметку ставит сам человек. У любой цели
появляется необязательная дата начала.

## Почему

Не у каждой цели есть естественное число: «найти работу», «пройти курс», «запустить проект», цель своими словами.
Сейчас ADR-007 требует единицу, старт и цель, поэтому мастер заставляет придумать «20 откликов» или «8 этапов». Это
противоречит правилу «никаких выдуманных метрик» и путает нового пользователя.

## Решения владельца · 2026-11-22

1. Цель без измерений имеет статус «В процессе → Достигнута», достигнутой её отмечает сам человек.
2. Дата начала нужна вместе со сроком окончания.

## Область изменений

- `packages/contracts/src/goals.ts` и связанные DTO (`GoalDetails`, `progress`, события)
- `packages/domain/src/core/goals.ts`, расчёт прогресса, команды измерений (запрет для такой цели)
- `packages/db`: схема `goals`, CHECK, репозитории, новая миграция
- `apps/web`: `goals-browser.tsx`, `goal-detail.tsx`, `goal-form.tsx` (правка), Dashboard и страница сферы, журнал действий
- Новый ADR (следующий свободный номер), строки в индексе ADR; `docs/api/contracts.md`, `database-schema.md`

## Задание

- [x] Вид цели: числовая (как сейчас) и без измерений. Название поля и значений фиксирует ADR. У цели без
  измерений `unit`, `unit_label`, `baseline`, `target`, `direction` пустые; у числовой они обязательны, как сейчас.
  Правило держат контракт, домен и SQL CHECK. Вид после создания не меняется.
- [x] Статус любой активной цели, числовой и без измерений (решения владельца 10 и 11 в LFS-223, для доски
  LFS-229): «Запланирована», «В процессе», «На паузе», «Достигнута». Переход между любыми двумя — ручная команда,
  время смены сохраняется («отмечена 15.11.2026», «на паузе с 10.11.2026»). Новая цель с датой начала в будущем
  получает «Запланирована», остальные — «В процессе»; дальше система статус сама не меняет, автоматической отметки
  «Достигнута» по 100% нет, процент числовой цели не зависит от статуса. Измерения можно добавлять в любом статусе,
  кроме архива. Архив — отдельный терминальный статус, как сейчас (ADR-007). Смена статуса — команда с
  `Idempotency-Key` и событием журнала, как остальные команды целей (ADR-008). В панели: у цели без измерений
  главная кнопка — «✓ Отметить достигнутой» или «↺ Вернуть в работу», у любой цели все переходы — в меню «⋯»
  («Начать», «Поставить на паузу», «Продолжить», «Отметить достигнутой», «Вернуть в работу»).
- [x] Цели без измерений нельзя добавить измерение: API отвечает 409 или 400 (выбрать в ADR), SQL не даёт вставить
  строку.
- [x] Дата начала — необязательное поле любой цели. Если заданы обе даты, начало не позже срока. Как дата
  переводится в момент в поясе пользователя — по образцу срока (ADR-010), записать в ADR.
- [x] Прогресс цели без измерений: процента нет, статус и объяснение — по контракту из ADR («В процессе» /
  «Достигнута»), а не «Недостаточно данных».
- [x] `/goals` (макеты 32, 36): у строки цели без измерений нет полосы прогресса; справа чип «В процессе» или
  «✓ Достигнута», под названием «сфера · с <начало> · до <срок>» или «сфера · отмечена <дата>». Панель «В процессе»
  (макет 36): крупно «В процессе», «с <начало> · N дней до срока», пояснение «Процента нет…», главная кнопка
  «✓ Отметить достигнутой», описание, «Как считается ›» и «История изменений ›». Панель «Достигнута» (отдельного
  макета нет, решение владельца): крупно зелёным «✓ Достигнута», «отмечена <дата>» и «◉ ручная отметка», пояснение
  «Цель снова станет «В процессе», если вернуть её в работу. Отметка останется в истории.», вторичная кнопка
  «↺ Вернуть в работу» на месте главной, описание и те же ссылки. Достигнутая цель остаётся во вкладке «Активные»
  (решение владельца, LFS-223); на доске это колонка «Достигнуты» (LFS-229). У числовой цели в статусе
  «Запланирована» или «На паузе» статус — чип рядом с названием (макет 32); в панели — чип рядом с названием цели.
- [x] Dashboard и страница сферы показывают такие цели без процента: число в процессе и достигнутых. Общий процент
  сферы не придумывается.
- [x] Правка (LFS-217): у цели без измерений меняются название, описание, дата начала и срок.
- [x] Создать цель без измерений через интерфейс можно будет в LFS-227 (мастер) и LFS-228 (новая цель). Здесь —
  API, отображение и тесты через API.

## Acceptance criteria

## Вне scope

Чек-листы и этапы (модуль Проекты, этап 9). Автоматическая отметка «Достигнута» у числовых целей. Перевод числовой цели
в цель без измерений и обратно. Пример целей (LFS-218) не меняется.

### Что сделано

- **Контракт**:
  - `kind` (`numeric | unmeasured`) и объединение двух видов в `createGoalInputSchema`;
  - числовая ветка — `createNumericGoalInputSchema`, ею пользуются мастер, пример и «Новая цель»;
  - `phase`, `phase_changed_at`, `starts_at` в `Goal`, команда `{ phase }` в PATCH;
  - правило «начало не позже срока»;
  - прогресс `unmeasured` со словом статуса;
  - снимок аудита с `kind`/`phase`/`starts_at`, `changed_fields` `starts_at`/`phase`;
  - `ActivityEntry.startsAt`/`phase`, `DashboardActivity.phase`.
- **Домен**:
  - `setPhase` (тот же статус — без события, архив — 409);
  - статус новой цели по дате начала (в SQL, время БД);
  - правка дат с проверкой против сохранённой второй даты;
  - определение цели без измерений — 409;
  - измерение такой цели — 409;
  - прогресс и журнал;
  - отпечаток создания без значений по умолчанию LFS-225.
- **БД**:
  - миграция `0010_goal_phases` (`pnpm db:generate --name goal_phases`), в конец дописана строка
    `phase_changed_at = created_at` для существующих целей;
  - CHECK вида, статуса и даты начала;
  - новые CHECK снимков событий и операции `phase` в квитанциях;
  - репозиторий: `create` с видом и статусом, `setPhase`, `starts_at` в правке.
- **Web**:
  - **Сервер.** PATCH различает архив, статус и правку.
  - **Строка списка.**
    - Числовая цель в статусе «Запланирована», «На паузе» или «✓ Достигнута» — чип у названия.
    - Цель без измерений — чип статуса справа вместо полосы.
    - Под названием «сфера · с … · до …», у достигнутой — «отмечена …».
  - **Панель.**
    - Чип статуса вместо «Активна».
    - У цели без измерений: крупно статус, «с … · N дней до срока» или «на паузе с …», у достигнутой «отмечена …»
      и «◉ ручная отметка».
    - Главная кнопка «✓ Отметить достигнутой» или «↺ Вернуть в работу» — один и тот же элемент, поэтому фокус
      остаётся на нём.
    - Раздела измерений у такой цели нет. «Как считается» объясняет, почему нет процента.
  - **Меню «⋯».** Все переходы из текущего статуса, затем «Изменить цель», «В архив», «Удалить цель».
  - **Форма правки.** Строка «Дата начала · Срок»: начало — начало дня в поясе пользователя (`startOfLocalDay`).
    У цели без измерений в форме только название, описание и даты.
  - **Журнал.** «Статус изменён: …», «Дата начала изменена: …».
  - **Dashboard.** У цели без измерений в строке сферы — статус. Факт смены статуса называется
    «Статус: Достигнута».
  - **Страница сферы.** Статус и «с …» / «отмечена …».
- **Тесты**:
  - contracts `goal-phases.test.ts`;
  - domain `goal-phases.test.ts`;
  - миграция: обновление с `0009` и CHECK;
  - HTTP + PostgreSQL `goal-phases.test.ts`;
  - web unit `goal-phases-ui.test.tsx`;
  - e2e `goal-phases.spec.ts`;
  - правки: фикстуры старых тестов (новые поля), `layout.spec` (первый пункт меню теперь переход статуса),
    `migrations.test` (новые колонки целей в сравнении старых обновлений).
- **`ui-shots`**:
  - в фикстуре цель без измерений в процессе (с описанием и датами), достигнутая цель без измерений и числовая на
    паузе;
  - новые снимки `goal-no-measure`, `goal-achieved`, `goal-phase-menu` против макета 36.
- **Документы**: ADR-013 и индекс ADR, `docs/api/contracts.md`, `database-schema.md`, `README.md` (маршруты).

### Ограничения

- Создать цель без измерений в интерфейсе пока нельзя: это LFS-227 (мастер) и LFS-228 («Новая цель»). Сейчас — через
  API, тесты и скриншоты создают её так же.
- Откат кода к LFS-224 после миграции несовместим с данными (ADR-013, «Миграция и откат»).
- «Пример» (LFS-218) при смене статуса остаётся примером: статус не считается правкой цели.
