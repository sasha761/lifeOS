# LFS-101 — Создать монорепозиторий LifeOS

**Этап:** 1 — Foundation  
**Зависимости:** нет  
**Цель:** рабочая структура проекта, готовая к установке приложений и пакетов, без бизнес-функциональности.

## Задание Codex

1. Проверь существующий репозиторий и `git status`. Не удаляй и не перезаписывай файлы без причины. Если это чистая папка, создай Git-репозиторий при необходимости.
2. Подготовь **pnpm workspace** и **Turborepo** с корнем `lifeos`; root `package.json` должен быть `private` и иметь поле `packageManager` (конкретная версия закрепляется в LFS-102).
3. Создай workspace-пакеты и приложения:
   - `apps/web` — будущий Next.js Web + Mini App + API;
   - `apps/worker` — отдельный Node.js runtime;
   - `packages/db` — будущая Drizzle schema и migrations;
   - `packages/domain` — независимые бизнес-правила и интерфейсы;
   - `packages/contracts` — общие Zod DTO и ошибки;
   - `packages/config` — общий TypeScript/ESLint config и env-schema.
4. Применяй понятные имена пакетов, например `@lifeos/web`, `@lifeos/worker`, `@lifeos/db`, `@lifeos/domain`, `@lifeos/contracts`, `@lifeos/config`. Определи `exports` и зависимости без циклов.
5. Добавь базовые `turbo.json`, `pnpm-workspace.yaml`, `.gitignore`, `.editorconfig`, `.gitattributes`, `.env.example` (без реальных секретов), placeholder-модули где требуется сборка.
6. Подготовь root scripts для `dev`, `build`, `lint`, `typecheck`, `test`; до установки соответствующих инструментов допустимы корректно описанные placeholders, но скрипты не должны маскировать ошибку фиктивным успехом.
7. В README коротко объясни, что продукт мультидоменный и что задачи 2–8 этапов пока не реализованы.

## Ожидаемые файлы

`package.json`, `pnpm-workspace.yaml`, `turbo.json`, `.gitignore`, `.editorconfig`, `.gitattributes`, `apps/*/package.json`, `packages/*/package.json`, workspace README. Уже существующие `AGENTS.md` и `docs/tasks/*` сохранить.

## Acceptance criteria

- [ ] Все шесть workspace-проектов видны pnpm (2 apps + 4 packages).
- [ ] Граф workspace-зависимостей без циклов, **нет** Vue/Nuxt, Laravel/PHP, Redis.
- [ ] Скелет можно установить без системных ошибок на утверждённой версии Node/pnpm (если версия ещё не зафиксирована — отметить ограничение).
- [ ] `.env.example` не содержит секретов, реальные `.env` игнорируются Git.
- [ ] Нет реализации auth, Telegram, goals, AI или учебных функций.

## Проверки

- `pnpm -r list --depth -1` — ожидаются все workspace пакеты.
- `git status --short` и `git diff --check` — нет случайных файлов/ошибок форматирования.
- Если рабочий pnpm отсутствует — показать требуемую версию и точные шаги установки; **не** объявлять проверку успешно пройденной.

## Вне scope

Не устанавливать всю экосистему из Master Plan сразу. Не создавать таблицы, реальную UI-страницу, CI или worker logic: это отдельные задания.

## Definition of Done

Структура monorepo зафиксирована, установка и workspace discovery проверены или документирован точный блокер, Codex подготовил список файлов/команд/открытых вопросов.
