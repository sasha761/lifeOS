# LFS-228 — Новая цель: мастер вопросов вместо формы

**Этап:** 2 — LifeOS Core (вставка после LFS-227, перед Stage 3, по замечаниям владельца 2026-11-21,
[STAGE-02-FEEDBACK](STAGE-02-FEEDBACK.md), п. 3.1)
**Зависимости:** LFS-208, LFS-227; макеты `42-goal-new`, `43-goal-new-steps`, `45-mobile-wizards` (LFS-223)
**Цель:** новая цель создаётся через наводящие вопросы с вариантами ответа и «Свой вариант», как в онбординге,
а не через форму с единицей, стартом и целью.

## Почему

Диалог «Новая цель» (`new-goal.tsx`, `goal-form.tsx`) сразу требует сферу, название, направление, единицу, старт и цель.
Владелец считает такой подход неудобным и выбрал вопросы с вариантами — тот же подход, что в мастере.

## Решения владельца · 2026-11-21

Создание цели — наводящие вопросы, варианты ответов и возможность ввести свой (STAGE-02-FEEDBACK, п. 3.1).

## Область изменений

- `apps/web/components/goals/new-goal.tsx`, маршрут `/goals/new` (диалог в `@modal` и отдельная страница)
- Компоненты вопроса из `apps/web/components/onboarding/` — переиспользовать, не копировать
- Каталог v2 и сборка целей из `@lifeos/domain/onboarding`
- API создания нескольких целей одной транзакцией, если нужно (см. задание); `docs/api/contracts.md`

## Задание

- [ ] Шаги диалога:
  1. сфера (шесть сфер);
  2. вопрос сферы из каталога v2 с вариантами и «Свой вариант»;
  3. уточнения выбранного варианта — те же поля, что в мастере;
  4. предпросмотр «Что получится» и «Создать цель» (в Финансах при нескольких вариантах — «Создать N целей»).
  «Назад» не теряет ответов, Esc и «Отмена» закрывают диалог.
- [ ] Со страницы сферы («+ Цель в сфере») и с итога мастера («+ Добавить цель в другой сфере») открывается тот же
  мастер, первый шаг пропущен, если сфера известна.
- [ ] Каталог, сборка целей и проверки — общие с онбордингом: одна функция, без копии логики.
- [ ] Несколько целей создаются атомарно: все или ни одной, с `Idempotency-Key`. Способ (новая команда или
  пакетный запрос) выбирается в плане задачи и описывается в `contracts.md`.
- [ ] Старая форма создания удаляется, если её больше нигде не используют. Форма правки цели (LFS-217) остаётся.
- [ ] Диалог шириной 640 px (решение владельца, LFS-223), шкала шагов «Сфера → Вопрос → Уточнения → Проверка»;
  со страницы сферы шагов три и сфера видна чипом в заголовке (макет 43).
- [ ] 390 px: диалог на весь экран, шаги по макету 45.

## Acceptance criteria

- [ ] Unit: шаги, переход «Назад», сборка целей тем же кодом, что в онбординге.
- [ ] Integration: создание одной и нескольких целей, откат при ошибке одной, повтор с тем же ключом, чужой
  пользователь.
- [ ] e2e: цель со страницы `/goals`, со страницы сферы, «Свой вариант», две финансовые цели за раз.
- [ ] `pnpm verify`, `pnpm test:ui`, `pnpm build`, `pnpm test:build` зелёные (меняется маршрут в `@modal`); `pnpm ui:shots` и
  таблица отличий против макетов 42, 43 и 45.

## Вне scope

Ассистент, который создаёт цель из текста (этап 7). Шаблоны для сфер, которых нет в каталоге.
