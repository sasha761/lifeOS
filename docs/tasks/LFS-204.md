# LFS-204 — LifeOS Dashboard шести сфер

**Этап:** 2 — LifeOS Core  
**Зависимости:** LFS-203, LFS-207, LFS-208, LFS-210  
**Цель:** Показать LifeOS как целостный продукт, а не приложение одного языкового модуля.

## Область изменений
- `apps/web/app/(web)/dashboard`
- `packages/domain/core/dashboard` — aggregation
- `packages/contracts` — dashboard DTO
- integration/component tests

## Задание Codex
- [ ] Собери dashboard из типизированного реестра 6 сфер, с counts целей и прогрессом конкретных целей, если есть measurements.
- [ ] В каждой сфере отображай реальные цели / количество активных / ссылку к деталям; при отсутствии данных — «Нет целей» и CTA, а не 0% мнимого уровня.
- [ ] Блок последних действий строится из `activity_events` владельца, нормализует тип/дату/source; события без доступа скрыты.
- [ ] Блок «Сегодня» только из реально поддерживаемых Stage 2 данных (например, цели со сроком, последние измерения); не имитируй «предстоящие уроки» или «активность в Telegram».
- [ ] Агрегаты рассчитывай простыми SQL и/или типизированными domain services, без metric snapshots, materialized views, background projection.
- [ ] Проверь мобильную компоновку, загрузку/empty/error states, число запросов без N+1 по целям и авторизацию.
- [ ] Специальный Language Tutor в Stage 4 появится как расширение, но Dashboard Stage 2 не зависит от него.

## Acceptance criteria
- [ ] API aggregation integration tests с двумя пользователями, без данных и с данными.
- [ ] Playwright flow create goal→measurement→dashboard.
- [ ] lint/typecheck/test/build.

## Проверки / тесты
- [ ] Есть все 6 карточек даже без целей.
- [ ] Нет фиктивных процентов для пустых сфер.
- [ ] После создания/обновления цели Dashboard показывает те же данные, что goal details.
- [ ] Действия другого пользователя не появляются.
- [ ] UI доступен на мобильном.

## Вне scope
Графики языка, банковские данные, Kanban, AI рекомендации, глобальный Life Score.

## Результат LFS-204 · 2026-11-17

Ветка `lfs-204-dashboard` (от коммитов LFS-211). `/dashboard` показывает шесть сфер
из реестра с точными счётчиками и прогрессом конкретных целей, блок «Сегодня» с
активными целями со сроком и «Последние действия» из `activity_events` владельца.
Общего процента, Life Score, «уровня» сферы и демо-данных нет. Миграций, новых
зависимостей и ADR нет: чтение следует ADR-010 (один READ ONLY REPEATABLE READ
snapshot, пакетные owner-scoped SELECT). Решения владельца: ссылка в шапке
остаётся «Кабинет»; лимиты — 5 целей на сферу, 8 сроков, 10 событий.

### Реализовано и файлы

- Контракты: новый `packages/contracts/src/dashboard.ts` (`dashboardSchema`,
  лимиты), `dashboardResponseSchema` в `index.ts`. Strict DTO: ровно 6 сфер в
  порядке `DOMAIN_KEYS`; цели сферы — активные, своей сферы, не больше счётчика;
  сроки — активные с `due_at` по возрастанию; события — по убыванию времени,
  `measurement` только у `goal_measurement.*`.

### Ограничения

- Лента событий сортируется по времени по всем сферам пользователя; индекс начинается
  с `(user_id, domain_key, …)`, поэтому PostgreSQL сортирует top-N. Для объёмов Stage 2
  это приемлемо; индекс `(user_id, occurred_at, id)` — отдельная миграция при росте.
- В ленте показывается текущее название цели, а не название на момент события
  (audit по ADR-008 не хранит названия).
- «Сегодня» — только цели со сроком из Stage 2; задачи, встречи, уроки не имитируются.
