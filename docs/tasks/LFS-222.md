# LFS-222 — Удалить ритм отметок

**Этап:** 2 — LifeOS Core (вставка после LFS-221, перед Stage 3, по замечаниям владельца 2026-11-21,
[STAGE-02-FEEDBACK](STAGE-02-FEEDBACK.md))
**Зависимости:** LFS-219, LFS-220; [ADR-012](../adr/012-onboarding.md)
**Цель:** ритм отметок убран из продукта целиком: шаг мастера, Настройки, API и колонка БД. Часовой пояс меняется
только в Настройках.

## Почему

Ритм ничего не меняет: напоминаний нет до Stage 3, а лишний шаг удлиняет мастер. Кроме того, шаг «Ритм» —
единственное место мастера, где подтверждается часовой пояс, хотя тот же выбор уже есть в Настройках («Язык и время»).

## Решения владельца · 2026-11-22

1. Ритм удаляется полностью: шаг мастера, блок в Настройках, поле в API и колонка `checkin_rhythm` вместе с
   сохранёнными значениями.
2. Часовой пояс уходит из мастера, его меняют в Настройках.

Ответ на вопросы плана — «сделай то что рекомендуешь» (2026-11-22):

3. Карточка «Ритм» справа на итоге убирается целиком. Строка «Главная: сначала N выбранных сфер» переходит во второй
   пункт «Что будет дальше»: «Откроется Кабинет, выбранные сферы будут первыми».
4. После проверок миграция `0009` применяется к основной базе владельца (`pnpm db:migrate`). Ветки до LFS-222 с этой
   базой больше не запускаются.

## Вне scope

Напоминания (Stage 3). Определение часового пояса по браузеру при регистрации. Риск: новый пользователь остаётся в
UTC, пока сам не сменит пояс в Настройках, поэтому срок цели может закончиться в другое время суток. Если это нужно
исправить, это отдельная задача.

### Что сделано

- **Контракт** (`packages/contracts/src/onboarding.ts`):
  - удалены `CHECKIN_RHYTHMS`, `checkinRhythmSchema`, `CheckinRhythm`;
  - в черновике нет `rhythm`, `timezone` и шага `rhythm`;
  - в `OnboardingState` нет `checkin_rhythm`;
  - `PATCH` принимает только два выбора попапа.
- **Домен**:
  - завершение мастера пишет в профиль только `focus_domains` и не трогает часовой пояс;
  - `update` обрабатывает только выбор попапа;
  - `readStoredOnboardingAnswers` читает черновик, сохранённый до LFS-222: отбрасывает `rhythm` и `timezone`, а шаг
    `rhythm` превращает в `summary`. Черновик с другими ошибками, как и раньше, не предлагается;
  - `CHECKIN_RHYTHM_OPTIONS` удалены из каталога.
- **БД**:
  - миграция `0009_drop_checkin_rhythm` (`pnpm db:generate`) удаляет CHECK `user_checkin_rhythm_check` и колонку
    `user.checkin_rhythm`;
  - схема `user` и репозитории без ритма; у unit of work нет `profile.setCheckinRhythm`.
- **Web**:
  - мастер — «Сферы → вопросы → Итог»; удалены `RhythmStep`, `RhythmPreview`, `moveDeadlines`, `rhythmLabel`,
    `focusLabel` и проп `timeZones`; даты показываются в поясе профиля;
  - шаг сфер: «Будет N вопросов по сферам и итог»; шкала: «…на каждую выбранную сферу и итог»;
  - итог: правой карточки «Ритм» нет, пункт 2 «Что будет дальше» — «Откроется Кабинет, выбранные сферы будут первыми»;
  - попап: пункт «8 · Ритм» заменён на «итог · Список целей, создаются только отмеченные»;
  - Настройки: строки «Ритм отметок» и `RhythmForm` нет;
  - `ui-shots`: черновик без ритма, снимок `onboarding-rhythm` удалён.
- **Тесты**:
  - contracts: новый черновик, `PUT` и `complete` не принимают ритм, пояс и шаг `rhythm`; `PATCH { checkin_rhythm }`
    и состояние с `checkin_rhythm` отклоняются;
  - domain: старый черновик читается и открывается на итоге, сломанный — нет; завершение пишет только сферы в фокусе;
  - web unit: шкала от 3 до 8 экранов, дата срока в поясе профиля;
  - PostgreSQL integration: завершение не меняет пояс (UTC и пояс, заданный в профиле); черновик LFS-221, записанный

    черновик целы, повторное применение безопасно; на чистой схеме колонки нет;

- **Документы**: ADR-012 (дополнение) и индекс ADR, `docs/api/contracts.md`, `database-schema.md`, `system.md`,

### Ограничения

- Черновик, сохранённый с поясом, отличным от профиля, покажет дату срока в поясе профиля. Она может сдвинуться на
  день (ADR-012, дополнение LFS-222).
- Код до LFS-222 не запускается на базе после `0009`: он читает `user.checkin_rhythm`. Основная база уже мигрирована.
- Новый пользователь остаётся в UTC, пока не сменит пояс в Настройках (см. «Вне scope»).

### Ручные действия

- Перезапустить `pnpm dev`, если он запущен с кодом LFS-221: старый процесс обращается к удалённой колонке.
