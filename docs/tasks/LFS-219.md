# LFS-219 — Мастер начальной настройки

**Этап:** 2 — LifeOS Core (вставка в очередь после LFS-218, перед LFS-220, по запросу владельца 2026-11-18)
**Зависимости:** LFS-218 (`goals.origin`, USD), LFS-217, LFS-202 (профиль), LFS-210 (аудит); [ADR-007](../adr/007-goals.md);
[ONBOARDING](../reference/ui/ONBOARDING.md) — вопросы, варианты и правила
**Макеты:** `24-onb-spheres.png`, `25-onb-question.png`, `26-onb-own-answer.png`, `27-onb-summary.png`,
`29-onb-mobile.png` (средний и правый экраны). Точные размеры — `docs/reference/ui/html/`.
**Цель:** человек отвечает на короткие вопросы по выбранным сферам и получает цели со своими цифрами.
Ничего не создаётся без его подтверждения.

## Почему

С пустым аккаунтом непонятно, с чего начать, а пример (LFS-218) — чужие цели. Мастер собирает то, что нужно
для работы с платформой: какие сферы важны, по цели в каждой с реальными стартом и целью, ритм отметок.

## Решения владельца · 2026-11-18
1. Шаги: **Сферы → по вопросу на каждую выбранную сферу в порядке реестра → Ритм → Итог** (от 4 до 9 экранов).
   Тексты вопросов и варианты — ONBOARDING.md, раздел «Вопросы».
2. В каждом вопросе — готовые варианты и «Свой вариант» с текстом; после выбора — уточнение цифр.
3. Любой вопрос можно пропустить, срок необязателен, ничего не создаётся до кнопки «Создать N целей».
4. Мастер не создаёт измерений: «сколько уже есть» и «сейчас» становятся стартом цели.
5. Точка входа в этой задаче — прямой адрес `/onboarding`. Попап и кнопку в Настройках добавляет LFS-220.

## Область изменений
- `packages/contracts` — новый `onboarding.ts`: каталог вопросов v1 (ключи сфер и вариантов, шаблоны целей),
  схема черновика ответов, DTO состояния и завершения, `checkin_rhythm`
- `packages/domain` — каталог как данные (не в компонентах), сборка предложенных целей из ответов
  (`buildOnboardingGoals`), команда `completeOnboarding(actor, answers, selected)`
- `packages/db` — миграция: таблица `onboarding_state` (`user_id` PK с каскадом от пользователя; `status`:
  `not_started` | `in_progress` | `completed` | `dismissed`; `choice`: `example` | `wizard` | `blank` | null;
  `answers jsonb`; `catalog_version`; `completed_at`; `updated_at`). `dismissed` и `choice` заводятся сразу, чтобы
  LFS-220 обошлась без миграции. Колонки профиля `focus_domains text[]` и `checkin_rhythm` (обе nullable, CHECK).
- `apps/web/app/(web)/onboarding/page.tsx`, `components/onboarding/*`; `app/api/v1/onboarding/route.ts`
  (`GET`, `PUT` черновика), `app/api/v1/onboarding/complete/route.ts` (`POST`)
- `apps/web/components/dashboard/*` — сферы в фокусе первыми
- новый ADR-012 «Начальная настройка» (что хранится, что создаётся, почему без измерений); `docs/api/contracts.md`

## Задание
- [x] Каталог вопросов v1 строго по ONBOARDING.md: тексты, варианты, подсказки, шаблоны (название, направление,
  единица из существующих `NOK`, `USD`, `count`, `minutes`, `percent`, `custom` + `unit_label`), лимиты выбора
  (Здоровье — до 3 вариантов, остальные — 1). Валюта финансов — NOK или USD. Языки: шкала A1–C2 → своя единица
  «уровень (A1=1 … C2=6)», название «<Язык> до <уровня>»; «Другой» — название языка текстом до 40 символов.
- [x] «Свой вариант»: текст 1–120 символов становится названием цели; пользователь выбирает направление
  («Увеличить до значения» / «Уменьшить до значения»), единицу (частые подсказки или своя), «сейчас», «цель», срок.
  Проверка теми же правилами, что при создании цели; ошибка показывается у поля на шаге, а не на итоге.
- [x] Шаги и навигация (`24`–`27`): шкала шагов строится по выбранным сферам; «Назад» без потери ответов;
  «Пропустить вопрос»; «Сохранить и выйти» сохраняет черновик на сервере (`status = in_progress`) и ведёт на
  `/dashboard`; повторное открытие `/onboarding` продолжает с того же шага. Справа панель «Что получится»
  обновляется по ходу ответа.
- [x] Ритм: «Каждый день», «2–3 раза в неделю», «Раз в неделю», «Сам, без напоминаний» → `checkin_rhythm`;
  подтверждение часового пояса из профиля. Напоминания не включаются (Stage 3).
- [x] Итог (`27`): предложенные цели с галочками и «Изменить» (тот же редактор, что на шаге); пропущенные сферы
  с «Ответить сейчас»; невыбранные сферы — «+ Добавить цель в другой сфере» (диалог новой цели). Блок «Ритм»
  и «Что будет дальше». «Создать N целей» неактивна при N = 0.
- [x] `POST /api/v1/onboarding/complete`: одной транзакцией создаёт отмеченные цели (`origin = onboarding`,
  события `goal.created` с источником `web`), записывает `focus_domains`, `checkin_rhythm`, `status = completed`,
  `completed_at`, и ведёт на `/dashboard`. Повтор с тем же `Idempotency-Key` не создаёт цели повторно. Ошибка в одной
  цели — не создаётся ни одна, ответ указывает, какая цель не прошла.
- [x] Повторная настройка (вход из Настроек появится в LFS-220): новые цели добавляются к существующим, ничего
  не удаляется; прошлые ответы подставляются как черновик.
- [x] Dashboard: сферы из `focus_domains` показываются первыми (сортировка в UI; порядок в DTO остаётся `DOMAIN_KEYS`).
- [x] Мобильный вид (`29`): шаг на весь экран, «Пропустить» и «Далее» закреплены снизу, уровни A1–C2 сеткой
  из 6 колонок.
- [x] Доступность: каждый шаг — `fieldset` с вопросом в `legend`; радио и чекбоксы с клавиатуры; после «Далее» и
  «Назад» фокус на заголовке шага; шкала шагов с `aria-current="step"`.

### Ограничения

- Основная база не мигрирована: `pnpm db:migrate` (`0008_onboarding`) — только с разрешения владельца. Код задачи без
  миграции не запустится: Better Auth пишет пользователей через схему с новыми колонками.
- Попапа первого входа, кнопки в Настройках, `dismissed` и выбора `example`/`blank` в интерфейсе нет — это LFS-220.
  Вход в мастер пока только по адресу `/onboarding`.
- Напоминания по `checkin_rhythm` не включаются (Stage 3). `focus_domains` меняется только мастером.
- Повторная настройка предлагает прошлые ответы, и созданные цели можно создать ещё раз (галочки на итоге). Это
  следствие правила «ничего не удаляется»; дубликаты человек снимает галочкой.

### Дополнение · 2026-11-20, исправлено 2026-11-21: 404 в `pnpm dev`

Владелец открыл `/onboarding` в `pnpm dev` и получил 404. Причина не в мастере: Next 16.4.5 подмешивает catch-all
слота `app/(web)/@modal/[...catchAll]` (LFS-212) ко всем адресам, и строгое сопоставление маршрутов отбрасывает
страницы вне `(web)` — `/auth/*`, `/telegram` и новый `/onboarding` — как неполные: у `(web)` для них нет ни страницы,
ни `default`.

2026-11-20 включили `deprecated.looseRouteMatching`. Это было ошибкой: флаг меняет и production, и hosted CI на PR #7
упал на build smoke — неизвестные сферы (`/domains/seventh`, `/domains`, `/domains/finance/unknown`) отвечали
пустой страницей с 200 вместо 404. Локально тогда запускался только `pnpm test:ui`, который 404 не проверяет.

2026-11-21 флаг убран, catch-all перенесён в `app/(web)/@modal/goals/[...catchAll]`. Из открытого диалога
можно уйти только назад в истории или на созданную цель `/goals/<id>`: страница под модальным `<dialog>` неактивна.
