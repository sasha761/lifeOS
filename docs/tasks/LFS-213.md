# LFS-213 — Компоновка страниц Stage 2 по макетам

**Этап:** 2 — LifeOS Core (вставка в очередь **после LFS-209, перед Stage 3**)
**Зависимости:** LFS-212, LFS-209; [ADR-011](../adr/011-design-system-v2.md); [UI_GUIDELINES](../UI_GUIDELINES.md); [PAGES](../reference/ui/PAGES.md)
**Цель:** страницы Stage 2 устроены так же, как на макетах. Разница допустима только там, где на макете
функции будущих этапов или данных, которых пока нет.

## Почему

LFS-212 перевела страницы на общие компоненты: цвета, шрифт, карточки и чипы теперь совпадают с `01-main.png`.
Сравнение `pnpm ui:shots` от 2026-11-17 показало, что компоновка многих страниц проще макетов, хотя данные для неё
уже есть:

| Страница | Макет | Сейчас |
|---|---|---|
| `/goals` | `09-goals`: список слева, справа панель выбранной цели | только список; цель — отдельная страница; во вкладках нет счётчиков |
| `/dashboard` | `04-progress`: компактный блок «Сферы жизни», по строке на сферу | 6 больших карточек сфер; «Последние действия» на пол-экрана; приветствие с email |
| `/domains/[domainKey]` | `10-domain-new-goal`: цели сферы и «Последние действия в сфере» | две карточки-заглушки |
| Диалог «Новая цель» | `10-domain-new-goal`: Единица / Старт / Цель / Срок в одну строку | срок отдельной строкой с маской миллисекунд, открытое поле описания, длинная подсказка |
| `/settings` | `16-settings`: меню разделов слева, поля профиля, «Изменить пароль» | без меню, профиль текстом, лишние плитки «Часовой пояс / Сейчас / Язык» |

## Область изменений
- `apps/web/app/(web)/goals/**`, `dashboard`, `domains/[domainKey]`, `settings`, `@modal`
- `apps/web/components/goals/*`, `components/dashboard/*`, `components/settings/*`; `components/ui/*` — только
  если нужен новый общий компонент (например, меню разделов настроек)
- Чтение журнала действий с фильтром по сфере и по цели: `packages/contracts` (query DTO) → `packages/db`
  (repository) → `packages/domain` (reader) → `apps/web` (`GET /api/v1/activity`, решение 4).
  Только чтение, без миграций.
- `apps/web/tests/**` — тесты и e2e под новую компоновку; `apps/web/scripts/ui-shots.ts` — если меняется набор экранов
- `docs/api/contracts.md` — новый endpoint журнала; `docs/UI_GUIDELINES.md`, `PAGES.md` — если меняются правила или соответствие страниц

## Задание

### 1. `/goals` — список и панель цели (`09-goals`)
- [ ] От 1024px: две колонки, как в `html/09-goals.html` (`minmax(0,1fr) 440px`). Слева список, справа панель
  выбранной цели; выбранная карточка выделена, как на макете.
- [ ] Выбор цели — URL `/goals/[id]`, фильтры сферы и статуса сохраняются. На `/goals` без id выбрана первая цель
  текущего списка. Пустой список — пустое состояние, как сейчас.
- [ ] Панель: иконка, название, чипы (сфера, направление, срок), меню «⋯» (Изменить, В архив); большой процент
  или «Недостаточно данных»; полоса; плитки Старт / Сейчас / Цель / Осталось; формула и источник;
  «Замеры» с «+ Замер»; «История изменений» из журнала этой цели.
  «Осталось» — расстояние до цели в единицах цели и дни до срока, если срок задан.
- [ ] До 1024px — как сейчас: список, цель открывается отдельной страницей.
- [ ] Во вкладках счётчики «Активные N», «В архиве N» и жирный итог «N активных целей в M сферах». Числа берутся
  из существующего read model Dashboard (`activeCount`/`archivedCount` по сферам), без нового API.

### 2. `/dashboard` — только данные Stage 2 (`04-progress`)
- [ ] Шапка: заголовок и жирный итог («N активных целей в M сферах. K в архиве.»). Приветствие и строки с email и
  часовым поясом убрать: они есть в `/settings`. «Выйти» переносится в `/settings` (решение 2).
- [ ] Первый ряд по сетке макета (`380px minmax(0,1fr)`): слева «Сегодня» (сроки), справа «Последние действия»,
  не больше 5 записей, чтобы правый блок не вытягивал страницу.
- [ ] «Сферы жизни» — компактный блок, как на макете: по строке на сферу (точка цвета сферы, название, полоса,
  «X из Y ед.» самой новой активной цели сферы (решение 3), «+N», если целей больше). Сфера без целей — «Нет целей» и ссылка
  «Создать цель». Цель без измерений — «Недостаточно данных» без полосы. Общего процента сферы нет (AGENTS.md).
- [ ] Строка сферы ведёт на `/goals?domain_key=…`.

### 3. Страница сферы `/domains/[domainKey]` (`10-domain-new-goal`)
- [ ] После входа: активные цели сферы (существующий `GET /api/v1/goals?domain_key=`) и «Последние действия
  в сфере» (журнал с фильтром по сфере). Карточка «специализированный модуль появится позже» остаётся.
- [ ] Для гостя страница остаётся публичной и без личных данных, как сейчас (на это опирается build smoke).

### 4. Диалог «Новая цель» (`10-domain-new-goal`)
- [ ] Единица / Старт / Цель / Срок — одной строкой от 640px, на мобильном 2×2.
- [ ] Срок — поле даты без времени и миллисекунд; хранится как конец дня в часовом поясе пользователя (решение 1).
  Так же в форме изменения цели; старые сроки не меняются, пока не изменена дата.
- [ ] Описание свёрнуто под «+ Описание». Поле и контракт не меняются.
- [ ] Подсказка о точности NOK и количества — короткая, полный текст только при ошибке.
- [ ] Размеры — по `html/10-domain-new-goal.html`. Третий режим с макета, «Количество за период», не делается:
  его нет в контракте целей.

### 5. `/settings` (`16-settings`)
- [ ] Меню разделов слева (`220px minmax(0,1fr)`): «Профиль», «Язык и время» — якоря на секции.
  На мобильном меню над секциями. Разделов «Telegram» и «Приватность и данные» нет до их этапов (3 и 8).
- [ ] Профиль: «Имя» и «Email для входа» в виде полей только для чтения; «Изменить пароль» ведёт на существующий
  сброс через `/auth/forgot-password`; строка «Регистрация закрыта…», как на макете; кнопка «Выйти» (решение 2).
- [ ] «Язык и время»: выпадающие списки в ряд и пояснение под ними; плитки «Часовой пояс / Сейчас / Язык»
  убрать. «Начала недели» в контракте нет — вне scope.

### Общее
- [ ] Верхняя навигация не меняется (открытый вопрос в PAGES.md).
- [ ] Данные с макетов в код не переносить; цвета только токенами; новые компоненты — в `components/ui`.
- [ ] Журнал по сфере и цели: только владелец; чужие `goal_id`/`domain` дают пусто или 404 так же, как неизвестные;
  гость — 401; лимит записей; без миграции. Если для запроса нужен индекс, это миграция — согласовать в плане.

## Acceptance criteria
- [ ] До кода выписаны элементы каждого макета; после кода `pnpm ui:shots` и таблица отличий по UI_GUIDELINES §5
  для всех экранов. Отличия из раздела «Почему» закрыты или объяснены функциями будущих этапов.
- [ ] e2e: выбор цели в списке (URL, фильтры, клавиатура, фокус), панель на 1280 и отдельная страница на 390,
  страница сферы для вошедшего пользователя и для гостя, выход из нового места. Существующие проверки не ослаблены.
- [ ] Чтение журнала: тесты контракта, двух пользователей, гостя и лимита.
- [ ] `pnpm verify`, `pnpm test:ui`, `pnpm ui:shots` зелёные. Контраст ≥ 4.5:1, видимый фокус, без горизонтальной
  прокрутки на 390.

## Вне scope
Задачи, серия, график, «Цели недели», рекорды, достижения (`04-progress` — этапы 9–10); пункты навигации «Языки» и
«Ассистент»; разделы настроек «Telegram» и «Приватность»; статус «Выполненные»; сортировка «по сроку» (нужен API);
режим «Количество за период»; изменение имени и email; форма смены пароля без письма; светлая тема; изменения схемы БД.

## Решения владельца · 2026-11-17
1. **Срок цели — дата без времени.** Хранится как конец выбранного дня в часовом поясе пользователя.
   Уже сохранённые сроки не меняются, пока пользователь не изменит дату. «Сегодня» и карточки показывают только дату.
2. **«Выйти»** переносится из шапки Dashboard в карточку профиля в `/settings`.
3. **Строка сферы на Dashboard** показывает самую новую активную цель сферы (порядок read model).
4. **Журнал по сфере и цели** читается через новый endpoint `GET /api/v1/activity` с фильтрами `domain_key`
   или `goal_id`.
