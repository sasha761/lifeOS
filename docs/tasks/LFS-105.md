# LFS-105 — pg-boss и отдельный Node.js Worker

**Зависимости:** LFS-104  
**Цель:** доказать, что длительные фоновые операции можно выполнять вне Next.js без Redis.

## Задание Codex

1. Подключи `pg-boss` к той же PostgreSQL и совместимому драйверу/настройкам из LFS-104; уточни используемый API по закреплённой версии документации.
2. В `apps/worker` создай отдельную исполняемую точку входа `src/index.ts`; процессы Web и worker должны стартовать независимо. Worker запускает очередь, регистрирует обработчик `demo.ping` и логирует безопасный результат (`job_id`, correlation ID, status).
3. Сделай возможность послать demo-job **из CLI или dev-only script**, не добавляя публичный HTTP endpoint для постановки произвольных задач.
4. Добавь обработку ожидаемых ошибок, retries/backoff и безопасное завершение процесса по SIGINT/SIGTERM, закрытие соединений. Демонстрационный worker не должен потреблять LLM/Telegram API.
5. Настрой `pnpm worker:dev`, `pnpm worker:start` (или аналог), отдельные config/env проверки и опционально Docker service для local.
6. Сделай интеграционный smoke test: задача поставлена → worker обработал → состояние подтверждено; исключи flaky проверки «просто sleep 2 seconds».

## Acceptance criteria

- [ ] Запуск Web **не запускает** неявно worker; отдельный worker стартует в своём процессе.
- [ ] CLI job выполняется, результат измерим в PostgreSQL/логе/тесте.
- [ ] Повторяемая ошибка не приводит к бесконечному tight loop; retry policy ограничена.
- [ ] Остановка worker graceful; не остаются зависшие DB-соединения.
- [ ] Нет Redis, внешнего AI, Telegram и реального расписания уведомлений.

## Проверки

Запуск worker и CLI demo-producer; интеграционный тест на настоящем PostgreSQL; `pnpm typecheck` и `pnpm test` для worker. Приведи IDs выполненных jobs без приватных payload.

## Вне scope

Транзакционное доказательство atomic write+enqueue и idempotency — **LFS-107**. Не реализовывать бизнес-jobs будущих этапов.
