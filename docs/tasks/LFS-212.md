# LFS-212 — UI-kit и автоматическое сравнение с макетами

**Этап:** 2 — LifeOS Core (вставка в очередь **после LFS-204, перед LFS-209**)
**Зависимости:** LFS-211, LFS-204; [ADR-011](../adr/011-design-system-v2.md); [UI_GUIDELINES](../UI_GUIDELINES.md)
**Цель:** чтобы экраны совпадали с макетами по устройству кода, а не только на глаз: общие компоненты,
запрет «своих» цветов и скрипт, который кладёт рядом макет и реализацию.

## Область изменений
- `apps/web/components/ui/*` — новые общие компоненты
- `apps/web/app/(web)/**`, `apps/web/components/**` — перевод существующих экранов на компоненты без изменения поведения
- `apps/web/scripts/ui-shots.ts` (или `scripts/`) и скрипт `ui:shots` в `package.json`
- проверка «нет hex-цветов» в `pnpm lint`
- `docs/UI_GUIDELINES.md`, `docs/reference/ui/PAGES.md` — только если меняется список компонентов или страниц

### Что сделано

- **UI-kit** `apps/web/components/ui`: `PageHeader`, `SectionCard` (на основе `Card`, роль region
  или article, `variant="dashed"`), `StatCard`, `SourceLabel`, `ProgressBar` (нативный `<progress>`,
  цвет сферы), `DomainIcon` (заливка 20%, 22/30/44 px), `StatusChip` (тоны st-*, `neutral`, `outline`),
  `SegmentedChoice` (radio-группа в виде вкладок). `SegmentedTabs` расширен размером `sm`
  и фоном `bg-background` по макету (`.seg`), его классы переиспользует `SegmentedChoice`.
  Цвет сферы — `tone` в `lib/domain-presentation.ts`, тоны — `lib/tones.ts`.
- **globals.css**: `.page-title` 30/36 от 768px и 26/32 на мобильном; `action-compact`/`action-sm`
  (размеры `.btn`/`.btn.s` для мыши, 44px на сенсорных экранах); `field-label`; поля 38px для мыши;
  токены `--shadow-popover`, `--shadow-dialog` вместо `rgb(…)` в компонентах. Новых цветов нет.
- **Оболочка**: верхняя полоса во всю ширину с полями 28px, логотип 26px, «/ Раздел», pill 13px;
  контент 1180px, отступ сверху 16px.
- **Страницы** `/`, `/dashboard`, `/goals`, `/goals/[id]`, `/goals/new`, `/domains/[domainKey]`,
  `/settings` переведены на UI-kit. URL и API те же.
- **«Новая цель»** (макет 10): parallel slot `app/(web)/@modal` + intercepting route `(.)goals/new`.
  Ссылка внутри оболочки открывает диалог поверх текущей страницы (✕/«Отмена»/Escape — назад,
  фокус возвращается на ссылку); прямой заход на `/goals/new` — та же форма страницей.
  Форма: вкладки «Сфера», «Название», вкладки «Как считать прогресс», Единица/Старт/Цель, Срок,
  Описание, предпросмотр формулы с введёнными значениями, подвал «Отмена / Создать цель».
  По сравнению с LFS-208 изменился только способ показа (диалог), это согласовано с владельцем.
- **Lint**: правило `lifeos-ui/no-color-literals` (`apps/web/eslint-rules/no-color-literals.ts`)
  для `app/**` и `components/**`: `#rgb…#rrggbbaa`, `rgb(a)`, `hsl(a)`, `hwb`, `lab`, `lch`,
  `oklab`, `oklch`, `color-mix`, включая arbitrary-классы Tailwind; сообщение указывает на токены.
- **`pnpm ui:shots`**: `apps/web/scripts/ui-shots.ts` на общей фикстуре `scripts/ui-fixture.ts`

  `<экран>-compare.png` (макет | 1440 | 390) и `report.json` в `.cache/ui-shots`.
- **Тесты**: `tests/ui-kit.test.tsx` (8), `tests/no-color-literals.test.ts` (19, включая проверку
  подключения правила через реальный `eslint.config.ts`); `design-shell.test.tsx` — проверка
  тонов сфер под новый формат (те же требования: только токены, уникальный цвет у сферы);
  `goal-forms.test.tsx` — состояние «нет данных» проверяется на новой панели прогресса.
  e2e: новый сценарий диалога «Новая цель»; локаторы обновлены под новые подписи

### Ограничения

- Hosted CI не запускался; `ui:shots` и `test:ui` — локальные проверки (не CI gate).
- Подпись раздела в полосе под диалогом — «Цели» (по URL), а не раздел страницы под ним.
- Поле срока показывает маску с миллисекундами (точное время из LFS-208); упрощение до даты
  меняет смысл хранимого значения и вне scope.
- Цели и действия на странице сферы (макет 10) — кандидат в отдельную задачу.
