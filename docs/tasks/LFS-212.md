# LFS-212 — UI-kit и автоматическое сравнение с макетами

**Этап:** 2 — LifeOS Core (вставка в очередь **после LFS-204, перед LFS-209**)
**Зависимости:** LFS-211, LFS-204; [ADR-011](../adr/011-design-system-v2.md); [UI_GUIDELINES](../UI_GUIDELINES.md)
**Цель:** чтобы экраны совпадали с макетами по устройству кода, а не только на глаз: общие компоненты,
запрет «своих» цветов и скрипт, который кладёт рядом макет и реализацию.

## Область изменений
- `apps/web/components/ui/*` — новые общие компоненты
- `apps/web/app/(web)/**`, `apps/web/components/**` — перевод существующих экранов на компоненты без изменения поведения
- `apps/web/scripts/ui-shots.ts` (или `scripts/`) и скрипт `ui:shots` в `package.json`
- проверка «нет hex-цветов» в `pnpm lint`
- `docs/UI_GUIDELINES.md`, `docs/reference/ui/PAGES.md` — только если меняется список компонентов или страниц

## Задание
- [ ] Компоненты по `01-main.png` и `html/09-goals.html`:
  `PageHeader` (заголовок, подзаголовок, действия), `StatCard` (подпись, большое число, пояснение, источник),
  `SourceLabel` («◉ ручной ввод» и т. д.), `ProgressBar` (цвет сферы), `DomainIcon` (квадрат с заливкой 15–20%),
  `StatusChip` (тона st-*), `SectionCard` (заголовок + действие справа). Существующие `card`, `segmented-tabs`,
  `skeleton` используются, а не дублируются.
- [ ] `.page-title`: 30/36 от 768px и 26/32 на мобильном, как на макетах (сейчас 26/32 везде).
- [ ] Перевести на них `/`, `/dashboard`, `/goals`, `/goals/[id]`, `/goals/new`, `/domains/[domainKey]`, `/settings`
  без изменения поведения, URL и API. Сверять с `09-goals`, `10-domain-new-goal`, `16-settings`, `04-progress`.
- [ ] Проверка в `pnpm lint`: в `apps/web/app` и `apps/web/components` нет литералов цвета (`#xxx`, `rgb(`, `oklch(`),
  кроме `globals.css`. Падает с понятным сообщением.
- [ ] Скрипт `pnpm ui:shots`: Playwright входит тестовым пользователем (как e2e), снимает страницы из таблицы
  ниже на 1440×900 и 390×844 в `.cache/ui-shots/`, и для каждой делает файл `<страница>-compare.png`:
  слева макет из `docs/reference/ui`, справа реализация. Без новых зависимостей, если хватает Playwright.

  | Страница | Макет |
  |---|---|
  | `/dashboard` | `04-progress.png` |
  | `/goals` | `09-goals.png` |
  | `/domains/finance` | `10-domain-new-goal.png` |
  | `/settings` | `16-settings.png` |

## Acceptance criteria
- [ ] Существующие unit, integration и Playwright-тесты проходят без ослабления.
- [ ] `pnpm lint` ловит hex-цвет в компоненте (проверено на временном примере) и проходит на чистом коде.
- [ ] `pnpm ui:shots` создаёт скриншоты и сравнения; они приложены к отчёту с таблицей отличий по UI_GUIDELINES §5.
- [ ] `pnpm verify` зелёный. Контраст ≥ 4.5:1, видимый фокус, клавиатура.

## Вне scope
Новые экраны будущих модулей, светлая тема, изменения API и схемы БД, пиксельное сравнение (данные на макетах примерные).
