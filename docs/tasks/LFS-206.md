# LFS-206 — Ручные измерения целей и история изменений

**Этап:** 2 — LifeOS Core  
**Зависимости:** LFS-205, LFS-210  
**Цель:** Дать пользователю возможность вручную фиксировать реальный прогресс и исправлять ошибки без потери аудита.

## Область изменений
- `packages/db` — `goal_measurements`, миграции, индексы
- `packages/domain/core/goals` — measurements service/repository
- `packages/contracts` — measurement DTO
- integration/unit tests

## Задание Codex
- [x] Введи `goal_measurements`: `id`, `goal_id`, `user_id`, `value` (точный decimal), `measured_at`, `source`, `note?`, `created_at`, `updated_at`; при необходимости `idempotency_key` с корректным уникальным scope.
- [x] Добавь доменные команды create/update/delete measurement с проверкой владельца родительской цели; нельзя прикрепить запись к чужой цели.
- [x] Записывай событие `goal_measurement.created|updated|deleted` в общей транзакции; для edit/delete — минимальный audit snapshot, без мягкого «магического» изменения прошлых данных.
- [x] Определи порядок выбора current: последняя **по `measured_at`** запись с детерминированным tie-breaker; backdated измерение не должно случайно стать current.
- [x] Если измерений нет, `current=null`, прогресс не считается; `baseline` само по себе не является отдельным подтверждённым замером.
- [x] Спроектируй идемпотентность повторных POST и последующих PATCH/DELETE и ограничения дат/размера строк/значений.

## Результат LFS-206 · 2026-11-16

Реализовано в ветке `lfs-206-goal-measurements`. Contracts → domain → DB:
измерения manual с exact decimal, create/get/update/remove/current/history,
parent ownership, unit/time/size validation, transactional audit и durable
retries всех write-команд. Без измерений current=null, baseline не замер.
Порядок — measured_at DESC, created_at DESC, id DESC; updated_at не участвует.
Backdated разрешён, будущее до 5 минут; note trim/null/1..1000.
Архив читается, новые изменения запрещены. Правила —
[ADR-009](../adr/009-goal-measurements.md), supplements к ADR-007/008.

### Acceptance evidence

- [x] Два пользователя: reusable ownership contract read/update/delete,
  foreign parent create/current/history → NOT_FOUND; direct SQL owner/unit
  mismatch → 23503; попытки не меняют rows/events/receipts.
- [x] Current: no-data при nonzero baseline, out-of-order backdating,
  равные measured_at/created_at, UUID tie-breaker, note-only edit, перенос
  даты, удаление текущего до предыдущего и до null.
- [x] Exact numeric: соседние значения 9007199254740993.01/.02 не смешиваются;
  0.00000001 для minutes сохраняется; отрицательные/NaN/Infinity/overflow,
  лишняя дробная точность, неправильная единица и future dates отклоняются.
- [x] Повторы: 6 concurrent creates, 4 updates и 4 deletes дают по одному
  эффекту; delete replay после рестарта, create/update replay удалённого
  ресурса → NOT_FOUND без resurrection. Общий goal/measurement key scope,
  changed body/target/source/operation → CONFLICT, different users независимы.
- [x] Audit: before/after/changed_fields, privacy note, сохранение deletion
  target, no-op без timestamp/event. Competing edits сериализованы;
  measurement и goal archive используют общий parent lock.
- [x] Rollback: AFTER INSERT failure на event и receipt по отдельности
  откатывает create/update/delete, current, событие и ключ; повтор работает.
- [x] Миграции clean/reapply/upgrade, legacy goal hash/replay, lint/types,
  unit/integration/build/smoke — PASS.
