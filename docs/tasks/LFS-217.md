# LFS-217 — Правка старта и цели до первого измерения

**Этап:** 2 — LifeOS Core (вставка в очередь после LFS-216, перед Stage 3, по запросу владельца 2026-11-18)
**Зависимости:** LFS-205, LFS-206, LFS-207, LFS-213; [ADR-007](../adr/007-goals.md), [ADR-009](../adr/009-goal-measurements.md)
**Цель:** пока у цели нет измерений, пользователь может изменить её единицу, старт, цель и направление; срок
везде явно необязателен.

## Почему

ADR-007 запрещает менять определение цели после создания, чтобы правка не переосмыслила уже введённые
измерения. Пока измерений нет, переосмыслять нечего, а ошибка в старте или единице сейчас исправляется только
архивом и новой целью. Стартовый набор (LFS-218) создаёт цели с примерными стартовыми значениями, которые
пользователь должен суметь поправить под себя.

Срок в контракте и форме уже необязателен (`due_at` по умолчанию `null`, поле без `required`), но по форме
этого не видно. Владелец не хочет, чтобы срок воспринимался как обязательный.

## Решения владельца · 2026-11-18
1. Единица (и своя единица), старт, цель и направление меняются, **пока у цели нет измерений**. После первого
   измерения — как сейчас, только название, описание и срок.
2. Срок помечается как необязательный; пустое поле — цель без срока.

## Область изменений
- `packages/contracts/src/goals.ts` — расширение `updateGoalInputSchema`; `activity-events.ts`, `activity.ts` —
  новые значения `changed_fields`
- `packages/domain`, `packages/db` — команда правки с проверкой отсутствия измерений под блокировкой строки цели
- `apps/web/components/goals/goal-form.tsx`, `lib/goal-form-input.ts`, `lib/activity-presentation.ts`
- ADR-007 (дополнение), `docs/api/contracts.md`

## Задание
- [ ] PATCH цели принимает `unit`, `unit_label`, `baseline`, `target`, `direction` вместе с прежними полями;
  итоговое определение проверяется целиком теми же правилами, что при создании (направление, точность единицы,
  своя единица).
- [ ] Если у цели есть хотя бы одно измерение — 409 `CONFLICT` с понятной безопасной ошибкой, ничего не меняется.
  Гонка «добавление измерения ↔ смена единицы» не даёт измерения в старой единице у цели с новой
  (блокировка строки цели или проверка в той же транзакции; составной FK по `unit` уже защищает от несовпадения).
- [ ] Архивная цель не меняется (как сейчас).
- [ ] Аудит: `goal.updated` с before/after новых полей; журнал показывает «Старт изменён: 2 → 3»,
  «Единица изменена» и т. п.
- [ ] UI «Изменить цель»: при отсутствии измерений — поля Единица / Старт / Цель (и направление), как в диалоге
  создания; после первого измерения — короткая подсказка «Старт и цель фиксируются после первого измерения».
- [ ] Поле «Срок» в создании и правке подписано «Срок · необязательно»; в правке есть способ убрать срок.

## Acceptance criteria
- [ ] Тесты контракта: допустимые и недопустимые сочетания; integration: правка без измерений с аудитом, 409 при
  наличии измерения, гонка, чужой пользователь, архив.
- [ ] e2e: правка старта новой цели, затем измерение, после которого поля старта недоступны; цель без срока.
- [ ] `pnpm verify`, `pnpm test:ui` зелёные.

## Вне scope
Перенос цели в другую сферу, пересчёт или конвертация существующих измерений, правка после первого измерения.
