# LFS-108 — CI, автоматические проверки и воспроизводимые сборки

**Зависимости:** LFS-107  
**Цель:** каждый pull request автоматически проверяет качество кода и совместимость Web/worker/PostgreSQL.

## Задание Codex

1. Настрой workflow GitHub Actions **если репозиторий размещён на GitHub**; если нет — создай рабочий YAML для будущего подключения и проверь локально всё, что доступно. Права GitHub доступ не предполагай.
2. CI должен использовать версию Node/pnpm из `LFS-102`, устанавливать зависимости через frozen lockfile и запускать (в зависимости от фактических scripts): `lint`, `typecheck`, `unit tests`, **integration tests с настоящим PostgreSQL**, `build` для Web и worker.
3. Включи PostgreSQL service container с отдельной тестовой БД и запуск миграций без персональных секретов. Не используй продакшн `DATABASE_URL`; не разрешай командам CI удалять локальную/боевую БД.
4. Настрой cache для pnpm по lockfile; это оптимизация, а не замена проверок.
5. Скрипты в корне должны иметь ясные названия и корректные exit codes: не использовать `|| true`, `echo success` вместо тестов, заглушки, скрывающие пропуск.
6. Добавь минимум один unit-тест доменной утилиты/контракта, одну DB integration проверку и один build smoke; убедись, что тесты не зависят от порядка запуска.
7. Добавь локальный `pnpm verify` (или документированную эквивалентную цепочку), который повторяет логику CI.

## Acceptance criteria

- [ ] Все проверки реально проходят локально либо указаны конкретные недоступные зависимости и точные команды для повторения.
- [ ] Workflow содержит DB service и реальные интеграционные тесты, а не только lint.
- [ ] `pnpm install --frozen-lockfile` без интерактивных prompts.
- [ ] Нет secrets в workflow и в логах.
- [ ] Build Web и worker не требует продакшн Telegram/AI ключей.

## Проверки

Локально `pnpm verify`, `pnpm build`, `pnpm test:integration`; `git diff --check`. Если возможен запуск Actions — указать URL/run status только при реальном успешном выполнении.

## Вне scope

CD/deploy production, SaaS-платежи, E2E языкового сценария, AI-evals (позднее).
