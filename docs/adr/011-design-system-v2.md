# ADR-011 — Design System v2: тёмная тема, Inter, верхняя навигация

- **Статус:** Proposed (ожидает решения владельца проекта)
- **Дата:** 2026-11-17
- **Связанные задачи:** LFS-211; влияет на LFS-204 и будущие модули Tasks / Job Search.
- **Источник:** [LifeOS_Design_Tasks_Jobs_v0.2.md §16](../reference/LifeOS_Design_Tasks_Jobs_v0.2.md), [макеты](../reference/ui/README.md).

## Контекст

LFS-103 создал базовую светлую тему (зелёный primary, Segoe UI, левый сайдбар со сферами).
Владелец выбрал другой визуальный ориентир: плотный «рабочий» интерфейс в тёмной палитре
с фиолетовым подтоном, pill-переключателями и верхней навигацией, как в референсных роликах
похожей платформы. Брендинг, логотип и тексты чужого продукта не копируются; переносится
только стиль и UX-паттерны.

Ограничения, которые остаются в силе: Tailwind 4 через `@theme inline` в
`apps/web/app/globals.css`, shadcn `base-nova` с CSS-переменными, lucide-иконки,
отсутствие внешних font-запросов в рантайме (apps/web/README), один Next.js app для Web и Mini App
([ADR-004](004-next-routing.md)), никаких фиктивных метрик.

## Решение

1. **Тема по умолчанию — dark.** Значения существующих shadcn-переменных в `:root` заменяются
   на палитру §16.2 спеки (`--background #16131D`, `--card #1F1A2A`, `--primary #8B7CF6` и т.д.),
   `color-scheme: dark`. Светлая тема откладывается; её значения остаются в спеке.
2. **Расширение токенов** в том же `globals.css`: поверхности `--surface-2/3`, `--border-strong`,
   `--text-3`, статусные `--st-*`, `--today`; проброс в `@theme inline` (`--color-st-blue` и т.д.).
   Отдельный пакет токенов не создаётся: Mini App живёт в `apps/web`.
3. **Шрифт Inter** самохостится: `next/font` (локальная выдача после сборки) или
   `@fontsource-variable/inter` с точной версией в lockfile. Выбор делает исполнитель LFS-211
   после проверки, что сборка в CI не зависит от сети; выбранный вариант дописывается сюда.
4. **Оболочка `(web)`**: левый сайдбар заменяется минимальной верхней полосой
   (логотип + текущий раздел слева, pill-кнопки справа), контент центрирован (~1180px).
   Навигация по шести сферам переносится в выпадающее меню «Сферы» и/или в карточки обзора.
   Кнопки модулей, которых ещё нет (Задачи, Проекты, Ассистент), не показываются.
5. **Форма элементов:** переключатели и кнопки — pill (`rounded-full`), карточки `rounded-2xl`,
   тонкие границы 1px, тени только у поповеров. Цвет используется только для смысла
   (сфера, статус, нагрузка).

## Альтернативы

- **Оставить светлую тему и добавить тёмную как опцию.** Отклонено на этом шаге: владелец хочет
  тёмный интерфейс основным, а две полноценные темы удваивают визуальную проверку.
- **Отдельный пакет `packages/ui` с токенами.** Преждевременно: единственный потребитель — `apps/web`.
- **Google Fonts по ссылке.** Противоречит правилу «без внешних font-запросов в рантайме».

## Последствия

- Все существующие экраны Stage 2 меняют вид без изменения поведения, URL и API.
- Playwright-сценарии LFS-208, завязанные на текст или роли, должны продолжать проходить;
  селекторы по классам цвета не используются.
- Нужна повторная проверка контраста: `--text-3 #857A99` на `--surface-2` даёт около 3.7:1,
  поэтому `--text-3` допустим только для плейсхолдеров/неактивного, а мелкий вспомогательный
  текст использует `--muted-foreground`.
- LFS-204 (Dashboard) строится сразу в новом стиле.

## Проверка

Заполняется после LFS-211: `pnpm verify`, Playwright desktop/mobile из LFS-208,
скриншоты `/`, `/dashboard`, `/goals`, `/goals/new`, `/settings`, `/auth/sign-in` на 1280 и 390 px,
проверка контраста и фокуса с клавиатуры. До выполнения — NOT RUN.
